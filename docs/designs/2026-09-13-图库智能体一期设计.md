## 修订记录

- **R3（2026-09-14，用户拍板方案 B）**：设计文档的"透传调用者 satoken"修订为**透传一组用户凭据（satoken + Spring Session 会话标识）**。原因（档 1 冒烟实测）：图库的空间列表/详情读 Spring Session（`SpaceController:142` → `UserServiceImpl.getLoginUser`），**不吃 sa-token**；空间维度的图片读另有加强校验 `checkSpaceViewPermission`（`PictureServiceImpl:768-786`），要求 Spring Session 用户与 sa-token 的 loginId **一致**——只带 satoken 时前者回 40100、后者回 SPACE_NOT_LOGIN。落地：引擎 headless 端点从 `SESSION` cookie 取会话标识并随工具下发（缺任一把在入口即拒，不再拖到工具调用阶段才炸）；T10 代理一并转发该 Cookie。两把凭据均**只在请求生命周期内存流转**，不落库、不进日志、不作为对话记忆内容。另：工具返回与入参的 **id 一律字符串透传**（沿用图库 Long→String 防精度丢失约定；实测数字往返会把 19 位雪花 id 截断）。口径见 huoshan-picture `docs/decisions.md` 2026-09-14 两条。
- **R2 补充（2026-09-13，用户拍板"对话保留 SSE 模式即可"）**：引擎对话循环收敛为**仅 SSE 流式模式**——`BaseAgent.run()` 同步路径退役，`runStream` 事件循环经事件消费者接口统一承载（同步调用方如需结果走同一事件流的收集实现）；`lastStepKind` 等父子类字段通道收编进事件载荷；SSE 事件协议（step/answer/metrics/[DONE]）随之升格为跨服务显式契约，headless 端点与图库前端共同遵守。实施挂 huoshan-picture plan T8。
- **R2（2026-09-13，用户拍板）**："AI 模块移到图库项目目录下，后续在图库仓库开发、由图库 git 管理"。落地形态：huoshan-picture 仓库新增 `ai/` 目录——`ai/agent/`（MyManus 引擎整体迁入）+ `ai/image-search-mcp-server/`（MCP 搜图服务迁入），两个独立 Maven 应用（不并 reactor，工具链/版本隔离），各自独立进程；**运行时架构不变**（引擎无法并进图库 SB 2.7 进程——Spring AI 栈要求 SB 3.x；代理 + token 透传链路原样）。引擎端口需与图库 backend（8123）错开（实施时定，如 8124）。yu-ai-agent 仓库冻结归档（打 tag + 归档说明；其工作区中用户自己的 README 未提交改动届时与用户对齐处置）；其挂账任务 T1（教学遗留清理）移交本仓任务清单（可选），T2（README 对齐）作废。

## 背景与动机

yu-ai-agent（MyManus 通用任务智能体）缺少落地的业务场景；huoshan-picture（火山图库，已上线 https://www.lincode.online）有真实业务面（空间/RBAC、图片上传/搜索/批量抓取、审核、AI 扩图）但无智能体能力。两者技术栈不兼容（SB 3.5/Java 21 vs SB 2.7/Java 17），只能跨服务集成。用户目标：**图库真实功能优先**（面试叙事为副产品），愿意做生产化投入。

## 选型记录（关键决策及理由）

1. **场景**：一期 = 整理管家 + 选图入库代理；AI 审核助手为后续立项（复用 Listing 合规审查冻结设计）；运营周报不做。
2. **形态**：一步到位内嵌——图库前端新增 AI 助手界面，图库后端代理调用 MyManus headless 引擎；MyManus 原 Vue 前端冻结不演进。用户明确"界面改到图库项目中"。
3. **身份**：图库后端代理透传调用者凭据，工具集携带调图库 API——凭据只在内存流转，不落库、无绑定向导、无重绑（**R3 修订：凭据为一组——satoken + Spring Session 会话标识**，理由见修订记录）。图库登录有图形验证码（安全批次故意加固），程序化自动续期被挡死，代理形态使该约束不再构成问题。
4. **模型**：OpenAI 协议接入（`spring-ai-starter-model-openai`），base-url/api-key/model 全配置化，不绑死厂商（DashScope 兼容模式/DeepSeek/Moonshot/GLM/SiliconFlow/vLLM 均可）；主脑与 visionTagger 视觉模型独立配置。
5. **词表**：图库侧建 `tag` 表。依据：标签现硬编码于 `PictureController.listPictureTagCategory`（9 标签 + 5 分类），后端编辑不校验词表（`PictureServiceImpl.editPictureByBatch` 直接 `toJsonStr` 落库），AI 自由打标会让前端标签筛选脏数据化，必须有受治理的开放词表。
6. **工具风格**：业务系统走原生 @Tool，生态工具走 MCP（Pexels 搜图接入既有 `image-search-mcp-server`，其 MCP server 形态不变、零改动）；两种集成风格并存各有其位。

## 总体架构

```
┌─ 火山图库 huoshan-picture ──────────────────────────┐
│ 前端（Vue3/AntD）                                    │
│  └─ 新增 AI 助手界面：对话 + SSE 步骤折叠条可视化        │
│         │（同源，复用现有 Sa-Token 登录态）              │
│ 后端（SB 2.7）                                       │
│  └─ 新增 AI 代理模块：服务间认证 + 用户上下文透传         │
│      + SSE 转发 ──────────────┐                      │
└───────────────────────────────┼──────────────────────┘
                                ▼
┌─ MyManus（yu-ai-agent，headless 引擎）───────────────┐
│  图库助手端点（服务间 API key 门槛，对外只服务图库代理）   │
│   └─ ReAct 循环（≤20 步，OpenAI 协议模型）             │
│       ├─ 图库工具集（@Tool，prototype 化，携带透传 token）│──▶ 图库 API
│       ├─ MCP client ──▶ image-search-mcp-server      │
│       └─ visionTagger（OpenAI 协议多模态）             │
└──────────────────────────────────────────────────────┘
```

调用链定为**图库后端代理**而非前端直连 MyManus：前端只和图库后端说话（同源无跨域、现有鉴权全覆盖），MyManus 的登录面不暴露公网。

## MyManus 侧设计

### 图库工具集（粗粒度原则：一个工具 = 一个业务动作）

| 工具 | 包装 | 用途 |
|---|---|---|
| `listSpaces` | /space/list/page/vo | 找空间 ID |
| `listPictures` | /picture/list/page/vo | 拉图片清单（元数据） |
| `getTagCategory` | /picture/tag_category | 动态词表（标签/分类目录） |
| `visionTagger` | OpenAI 协议多模态批量看图 | 返回每图标签/分类建议（整理管家的"眼睛"） |
| `batchEditPictures` | /picture/edit/batch | 批量打标/分类/命名（整理落点，一次调用） |
| `batchUploadByUrl` | /upload/url 内部循环 | 选图入库落点，逐条报成功/失败/额度 |

- 看图收在 `visionTagger` 工具内（批量生成建议），与主脑解耦、单步完成 N 张图（步数友好）、可独立单测。
- `visionTagger` 提示词注入当前词表，规则："优先复用已有标签，词表缺了才提议新标签，新标签由图库自动注册"——词表有分寸地生长。
- 20 步预算靠粗粒度工具 + 结构化分页返回保障（`batchUploadByUrl` 在工具内部循环逐条调图库，agent 一步完成一批）。
- 工具集 prototype 化（per-request 实例注入 token 与图库地址），与"控制器按请求新建 MyManus"的既有决策对齐。

### 会话类型与 headless 端点

- 会话类型（普通 / 图库助手）决定工具注册表装配与系统提示词：图库助手只挂图库工具集 + MCP 搜图，不挂文件/终端等无关工具。
- headless 端点：服务间 API key 鉴权；请求携带外部用户标识（`huoshan:<userId>` 映射为 MyManus 会话归属）与调用者凭据（**R3：satoken + Spring Session 会话标识**）；SSE 输出复用现有步骤事件协议（前端折叠条按同一语义渲染）。

### 模型

- 新增 `spring-ai-starter-model-openai` 依赖；多 ChatModel 并存装配，按会话类型注入（手动编排的工具循环中 ChatModel 显式传入，无侵入）。
- 图库助手主脑 = OpenAI 协议文本模型（配置项指定；默认候选 DashScope 兼容模式 qwen-plus，换厂商只改配置）。
- `visionTagger` = OpenAI 协议多模态（`image_url` 输入），独立配置项，可与主脑不同家。
- 普通会话维持本地 Ollama 默认不变（现有 profile 机制不动）。
- MCP client starter 已在 pom（`pom.xml:88`），接入 image-search-mcp-server 零新增依赖。

## 火山图库侧设计

### 标签词表

- 新表 `tag`：`id, name(唯一), type(tag|category), usage_count, is_delete, create_time, update_time`；全局词表不按空间拆（词表碎片化对 AI 打标是灾难；团队空间隔离词表留二期演进）。
- `/tag_category` 查表动态化，**返回结构 `PictureTagCategory{tagList, categoryList}` 逐字段不变**（前端标签筛选无感）；现有 9 标签 + 5 分类作为种子数据迁移。
- 编辑接口（单编/批编）写入 tags/category 时**同事务 upsert 词表并累加 usage_count**；`picture.tags` JSON 列与 LIKE 查询逻辑完全不动（搜索兼容零风险）。

### AI 代理模块 + 前端助手界面

- 后端：新增代理端点（转发对话请求到 MyManus，附服务间 API key + 当前用户 satoken + 用户标识），SSE 流转发（SB 2.7 实现选型实施时定：SseEmitter / OkHttp EventSource）。
- 前端：AI 助手入口 + 对话面板 + SSE 步骤折叠条（消费 MyManus 现有事件协议语义，AntD 组件渲染）。

## 安全设计

- MyManus 图库助手端点：只接受服务间 API key，不注册登录体系；建议与图库同机/内网部署。
- 权限继承：所有图库操作以用户 satoken 走真实 API，RBAC 由图库服务端判定，引擎无越权能力（对象级鉴权口径继续生效）。
- token 生命周期 = 请求生命周期，不落库不持久。
- 一期不注册删除类工具（整理只增改不删）；TerminalOperationTool 维持不注册。
- Pexels 免费档限流：超限报错不重试。

## 验收标准

1. 图库前端登录后打开 AI 助手界面，对话可用，SSE 步骤折叠条逐步可视化。
2. "把空间 X 里没分类的图按内容打标分类" → agent 分批整理，折叠条每步可见，结果在图库图片列表可核对（含词表自动生长、usage_count 正确）。
3. "找 10 张 XX 主题的图放进空间 Y" → 空间出现新图、额度记对、失败逐条可见。
4. 双仓门禁绿：图库新增集成测试（词表/代理）；MyManus 新增单测（工具集 Mock HTTP、visionTagger 打标解析、端点鉴权）。

## 已知限制

- SB 2.7 后端做 SSE 转发的实现选型实施时定（SseEmitter / OkHttp EventSource）。
- MyManus 服务间端点公网暴露需 API key + 部署约束（内网/同机优先）。
- 视觉模型读 COS 图依赖图片 URL 可公网访问（私有空间签名 URL 可用性实施时确认）。
- image-search-mcp-server 作为独立进程运行（部署打包方式实施时定）。
- 词表全局共享，团队空间隔离词表留二期演进。
- MyManus 普通对话前端冻结；是否物理删除由其收尾清理任务 T1 另议，不自动删。

## 双仓任务映射（概要，实施计划各自细化）
