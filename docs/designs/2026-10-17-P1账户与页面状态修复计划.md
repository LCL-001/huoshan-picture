# T68–T70：项目级 review 前三项 P1 修复计划

## 授权与边界

2026-10-17 用户要求“先修前三项 P1，先写计划再执行”。仅收敛旧 Session 换绑接管、编辑转上传误覆盖、跨身份私有页面残留；其余九项 P2 不在本批。spec 关键三行、表结构、依赖、进程与服务端资源 RBAC 不变。

## 顺序与方案

1. 先落本计划、plan 索引与功能说明，文档单独提交，再改实现。
2. T68：邮箱绑定在验证新邮箱验证码、更新邮箱之前校验双登录态且身份一致。复用 T56 的 LoginSessionValidator，避免引入 UserService 与 validator 的循环依赖；保留请求入口既有方法，必要时抽出只接收已登录用户的静态校验。此处不将 Spring Session 全局失效，也不新增版本表或 Redis 会话版本机制。旧 Session 不能再用于改变账号找回渠道。
3. T69：上传页随图片 id / 空间上下文变化重新初始化；清除旧图片与表单，旧请求的延迟回包不得重填新页面，正常编辑/文件上传/URL 上传保留原契约。不修改全局路由语义、不改变 id 字符串透传。
4. T70：KeepAlive 容器绑定当前登录身份，在退出或账号切换时销毁旧缓存，而不是只为不同身份积攒不同 key。空间拒绝刷新不保留旧内容/权限；正常同账号详情往返继续缓存。
5. 两项前端允许在互不重叠的文件范围并行，后端与集成由主线程负责。

## 必须先红后绿的验收

- T68：旧 Session + 缺失/已撤销 Sa-Token、异人 token 拒绝；邮箱验证码不得被消费、邮箱不得更新。同人有效凭据可继续正常绑定；密码重置的既有 Sa-Token 撤销回归保持绿。
- T69：编辑 A→无 id 新增、A→B、空间变化、旧请求延迟返回；断言实际上传请求装配与组件状态，不只匹配源码字符串。
- T70：Vue 真实内存 renderer 或等效组件执行覆盖 A 空间→退出→B→返回；验证旧实例已销毁、旧私有数据不显示；无权刷新清空数据；同人往返仍命中缓存。

## 回归、提交与证据

每项先新增永久测试并保存预期失败输出，再修到绿；后端纯单测、前端 type-check、只读 eslint、现有纯函数断言与构建通过。每个任务单独 conventional 代码提交，不混文档；文档计划及收口独立 docs 提交，不绕门禁。运行结果写不可变 records，plan 只更新状态与指针，同日增量追加已有 handoff。无真实数据服务时明确标注未做 HTTP/MySQL/Redis/COS 端到端，不用模拟结果冒充真机证据。

## 不做

不重构全站身份体系，不处理旧 Session 的其它已接受残余；不修本批之外的缓存筛选、配额、回收站、WebSocket、AI 超时/并发等 P2；不接触现有未跟踪目录，不删除文件，不推送或部署。
