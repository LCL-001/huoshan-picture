## 排障记录（本会话重要教训）

1. **matchIfMissing 陷阱（最值钱的一条）**：`spring-ai-starter-model-openai` 的六条模型自动装配**全部** `matchIfMissing = true`，属性缺省即启用。只加依赖不改 yaml 的实测结果是启动直接崩——`BeanCreationException: Error creating bean with name 'openAiAudioSpeechModel' … OpenAI API key must be set`。加守卫后六条全落 Negative matches。**以后接任何 Spring AI provider starter，先查它的 autoconfigure 条件是否 matchIfMissing**；反查方法：解 jar 读 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`，再 `javap -v <class>` 看 `@ConditionalOnProperty` 的 havingValue/matchIfMissing。
2. **容器里不能再多一个 ChatModel Bean**：`ChatClientAutoConfiguration#chatClientBuilder(ChatModel)` 是按类型取**单个** ChatModel（javap 反查字节码确认），容器已有 profile 决定的默认模型，再注册就是 `NoUniqueBeanDefinitionException`。所以 T6 用持有器。**T7/T8 要模型请从 `OpenAiChatModels` 取（`assistant()` / `vision()`），不要改成 Bean 注册。**
3. **base-url 不能带尾部 `/v1`**：Spring AI 的请求路径自带 `/v1/chat/completions`，带 `/v1` 会拼成双 `/v1` 报 404（探针实测）。第一版示例写错，已修。DashScope 兼容模式填 `https://dashscope.aliyuncs.com/compatible-mode`。
4. **本机 Maven 本地仓库不在 `%USERPROFILE%\.m2\repository`**，而在 `D:\develop\Maven\apache-maven-3.9.11\maven_repo`（查版本、解 jar 别查错目录——本次先查错了一次）。
5. **验证"测试真的会红"的两个细节**：①`mvn test` 每次都会 process-resources 把 src 的 yaml 覆盖回 target，改 `target/classes` 副本做负向探针后要跑 `mvn surefire:test`（不要再跑 `test`），否则白改；②探针值必须**真的会触发故障**——第一次把 `image: none` 改成 `ollama`，而 `ollama` 同样不会启用 OpenAI 装配，探针不出红，差点误判"测试无效"。正确探针是"删掉该行"（缺省→matchIfMissing）与"改成 openai"，两者都实测红。
6. **Windows/PowerShell 小坑**：cmd 传 `$` 给 PowerShell 会被吞（`\$false` 转义失败）；含 JSON/中文的临时文件用 Write 工具或 .NET `[IO.File]::WriteAllText` 落**无 BOM** UTF-8，别用 `Set-Content -Encoding UTF8`（PS 5.1 写 BOM，Ollama 直接 400 `invalid character '?'`）。
