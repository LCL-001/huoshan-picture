**两个坑（都写进脚本注释了，值得记住）**：
- MySQL 的 `LIKE` **不支持 `[_]` 字符类**（那是 SQL Server 语法）。写 `'sec[_]%'` 会匹配 **0 条**、把 15 个账号静默漏删，而脚本仍然"成功"退出。**精确前缀一律用 `left(col, N) = 'x'`。**
- **不能照账号名猜是不是探针**：我一开始把 `1234`～`1234567`、`admin` 都列成"历史探针"，盘点内容足迹后发现 `1234` 有 144 张图、`admin` 是管理员。**删之前必须看属主的真实足迹。**

### 3. 引擎启动必要条件实测（`9a263a9`）—— 本次最有价值的一条

把清单里原先标着"本机没验证过"的那条验掉了，结果**它真的会让首次部署失败**：

| 做法 | 结果 |
|---|---|
| `AI_DASHSCOPE_API_KEY` 为空 | 启动失败：`DashScope API key must be set` |
| 把 `spring.ai.model.chat` 关成 `none` | 启动失败：`Parameter 1 of constructor in FlowWindowBasedChatMemory required a bean of type ChatModel that could not be found` |

**结论：prod 必须给一个真实可用的 DashScope key**——哪怕助手的大脑是 MiMo（OpenAI 协议）。而且**它不是摆设**：`FlowWindowBasedChatMemory.summarize()` 里真的会 `chatModel.call(...)`，**长对话的摘要压缩走的就是这条链路**，给假 key 能启动、会话一长摘要就失败。想摆脱这个耦合得改代码（摘要改走 MiMo / 让该注入可选），属独立任务。
