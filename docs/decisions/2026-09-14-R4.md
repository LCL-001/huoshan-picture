## 决定

**R4/R6 收口（用户拍板"R4 同意加校验、R6 做"）**：**R4** 代理入口新增**身份一致性校验**——`StpKit.SPACE.getLoginIdByToken(satoken)` 必须非空且与 Spring Session 登录用户同 id，否则直接拒绝、零上游请求：**无效/过期 → 40100，有效但不属于同一人 → 40102**（与 `checkSpaceViewPermission` 同口径）。这一刀**推翻**原"代理只判凭据存在性、不判身份"的已决口径（按规则 2 经用户同意），但**仍不判权限**：能不能看某个空间只由图库服务端判。同时**更正**上文 2026-09-14"凭据组口径（B 落地）"条里"不一致时回 SPACE_NOT_LOGIN"的适用范围——该判据只对空间维度读图成立，`listSpaces` 一类路径只由 Spring Session 授权，故一致性必须由代理自己补。**R6** 新增 `AiPathSaTokenGuardTest` 反射守护三条不变量（/ai/** 控制器零 Sa-Token 注解；凡用注解的控制器路径必须落在拦截路径覆盖内；拦截路径不含 /ai/**），并把拦截路径清单提取为 `SaTokenConfigure.ANNOTATION_GUARDED_PATTERNS` 供断言

## 理由

R4 依据 review 实测的洞：真会话 + 假 token `review-bogus-token` 仍能让引擎读到真实空间，根因是"只判存在性"使"透传一组凭据"退化为"放行任意非空白 token"，而代理是唯一能在入口发现错配的地方（引擎不自行校验、`listSpaces` 也不校验）。实现只用 Sa-Token 现成 API（`getLoginIdByToken` 只查 DAO、找不到/invalid 返回 null、不抛），只做一次身份比对、不复制权限逻辑。R6 依据：Sa-Token 注解在未注册路径上静默失效（比不写更危险），原先仅靠注释与文档承载；**两轮负向控制实测**（给助手端点挂 `@SaCheckLogin` → 2 条不变量红并报出 `AiAssistantController#chat`；把 `/ai/**` 加进拦截路径 → 第 3 条红），证明守护测试不是空转
