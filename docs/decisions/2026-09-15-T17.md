## 决定

**T17 助手侧按角色裁剪看图打标工具（用户 2026-09-15 拍板"普通用户助手里的只读 visionTagger 摘掉"）**：① 新增**调用者角色信道**——backend 代理把 `loginUser.getUserRole()`（空值按 `UserConstant.DEFAULT_ROLE`）放进 `X-User-Role` 头，随 satoken / SESSION 一起透传（同走服务间密钥那条信道）；② 引擎装配 `HuoshanToolFactory.assistantTools(client, visionModel, canTagPictures, extraTools...)` 新增开关，`visionTagger` **只在"配了视觉模型 且 调用者是管理员"时挂载**；③ 判定 `HuoshanAssistantSession.isAdmin(role)` **fail-closed**——头缺失、空串、未知值一律按普通用户（宁可少挂一个工具，也不默认多给一个）；④ 角色原文**不进日志**（与 `chatId` 同属请求头传来的可换行注入输入，只记布尔结果）。

## 理由

**为什么不复用 T15 的接口（plan T17 标题里那个"是否"；这一半是 AI 判定、用户未单独拍板）**：① T15 那两个端点是为**公共图库管理页**写的（`spaceId IS NULL` 走不通 `batchEditPictures` 才有它），而助手侧 `visionTagger` 服务的是**空间图片**（收 `spaceId`、经 `/picture/get/vo` 取地址）——两者覆盖面不同，接上去不是等价替换；② 复用会让助手多依赖一份**图库侧多模态配置**（`app.ai.vision.*`）与第二跳服务间调用，而引擎自己那组（`app.ai.openai.vision.*`）本就在用；③ T17 条目的文件范围只列了"代理 + `HuoshanAssistantController` + `HuoshanToolFactory`"，新增工具类超出范围（规则 1）。**未采纳的下一步（另行立条目才做）**：把管理员侧工具改调 T15、让打标提示词只留一份。**已知代价**：打标提示词仍在引擎 `VisionTaggerTool` 与 backend `PictureAiTagManager` 各存一份（T15 起就如此）。**副作用边界（重要）**：本机制只决定"引擎给模型看哪些工具"，**不是授权**——引擎校验不了这个头的真伪（能作假的调用方本就持有服务间密钥），而 `visionTagger` **只读**、且以调用者自己的凭据打图库 API，故越权的实际收益只是"多花一次 LLM 费用"；能不能看到/改到某张图仍只由图库服务端判 RBAC。**证据**：门禁 backend 70 → **74 例**、ai/agent 137 → **140 例**全绿；集成测试 `AiAssistantProxyIntegrationTest` 8/8（真实登录后桩引擎收到 `X-User-Role: user`）；两处负向控制实测会红——摘掉工厂开关 → "普通用户不含 visionTagger"那条红（报出多挂了 `visionTagger`），把 `isAdmin` 放宽为恒真 → 角色两条判定红。
