## 决定

**R5 收口口径（用户拍板"采用一次性 ticket"）**：`GET /ai/assistant/chat` 新增**必需参数 `ticket`**，由新增的 `POST /ai/assistant/ticket` 签发（走与 chat 同一套登录门槛）；票存 Redis（键 `huoshantuku:ai:assistant:ticket:<value>`，值为**签发用户 id**，TTL 60s），**用 `getAndDelete` 原子取用即删 = 单次使用**；`chat` 新增**门槛四**校验"票存在且属于会话用户"，否则 `40300`、零上游请求（门槛四置于三个登录门槛**之后**：登录过期仍回原来的 40100，且不会因身份不一致白烧一张票）。票虽在 query 里、会进访问日志，但**一次性 + 60s** 使其泄漏无害——这正是选它而非长效共享密钥的理由。**未采用**：① **改 POST + fetch 流式**（治本，且顺带解决"用户提问原文进 nginx access log"与 URL 长度上限，但要在前端手写 SSE 解析，而前端无测试脚本、存量 type-check 138 / eslint 73 例，照应 P3 里已有的"relay 多行 `data:` 产出半个 JSON 帧"这类分帧 bug——建议将来处理"提问进日志"时一并做）；② **sa-token 自带 `SaSameUtil` / `SaSameTemplate`**（1.39.0 源码已核，`cn.dev33.satoken.same`：全站**共享单值**存 `satoken:var:same-token`，`SaTokenConfig.sameTokenTimeout` 默认 `24h`，`checkCurrentRequestToken()` **只从 header 取**；EventSource 设不了 header 只能塞 query，一旦落进访问日志就是"整个部署 24h 内人人可用"的共享密钥，比单次票更差）；③ **两把 Cookie 改 `SameSite=Strict`**（一行配置但挡不住同站/被控子域攻击者，且外链首跳会以未登录呈现，故只算加固不算替代）。票**不是**图库凭据（非 satoken / 非会话标识），60s 后自行消失，不入 MySQL、不进日志

## 理由

根因：全站 CSRF 防线原是**隐含约定**——"`SameSite=Lax` + 有副作用的接口都是 POST"（跨站 POST 不带 Cookie、子资源请求不带 Cookie），而本端点为了迁就 `EventSource`（不能设 header、只能 GET）成了唯一的"GET 有副作用"例外，正好落在 Lax **唯一放行**的那条路（顶层导航）上；review 已实测（`127.0.0.1:8135` 页面 → `localhost:8131` 顶层导航带齐两把 Cookie 跑完一次 agent，同页 no-cors 子资源请求被 Lax 拦下回 40100）。修法必须利用"攻击者能构造请求但**读不到响应**"这一性质，ticket 正基于此。范围上只做单点收口（用户拍板），**通用方案**（全站拦 cross-site 的过滤器 + "GET 无副作用"守护测试 + CORS 白名单核实）已记入 plan.md 作为后续候选，用于覆盖将来新增端点
