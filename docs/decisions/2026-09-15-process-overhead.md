| 指标 | 实测 |

| AI 窗口（2026-09-13 起）提交 | 145 笔，其中 `docs:` **93 笔 = 64%** |

**关键归因**：那 7 处勘误**没有一处是"忘了写"，全部是"同一事实有两份、只改了一份"**。所以治理方向不是"少写文档"，而是**消除重复**与**砍掉非阻断项的收口闭环**。

## 六项改动

1. **文档归属（单一事实源）** — AGENTS.md 新增同节 + 表格定义每个文件的职责。核心规则：同一事实只允许出现在一个文件里，别处写"见 X"。判断标准是"这句话三个月后还成立吗"：成立 → decisions（口径）；只描述当时发生了什么 → handoff / records。
2. **字据收窄（规则 3）** — 字据只对四类改动强制（推翻已决口径 / 改关键三行 / 新依赖新进程新表 / 用户可见行为变更）；其余（内部加固、文档订正、测试补强、已知限制收口）不立字据、不开新任务。依据：T20 整个任务只为 T19 的并发正确性 + 两处文字精度；T21 三条 P3 里两条是纯文档。
3. **review 输出契约（规则 13）** — 结论只有两类：**现在修**（P1/P2，或廉价且用户可见）与**判为已知限制并关闭**（P3，写进功能文档即算收口，不建任务、不立字据、不写收口记录）。**禁止第三类"挂账"**。依据：R5 review 的 6 条 P3 挂了 5 天一条未做，却长期占着 decisions 里 1500 字的一行加 plan.md 一整段——**挂着比修和关都贵**。
4. **提交颗粒度（规则 7）+ 交接增量（规则 6）** — 字据在动手前单独提交；**收口记录并入 handoff**，不再单开一笔；handoff **一天一份、只写增量**（不复述"当前状态/刚完成"）。
5. **证据落定（规则 16）** — 证据分"可复跑"（脚本+文本，入库）与"不可复跑"（截图/大日志，标注"不可复跑，证据已过期"+ 复现步骤）。**禁止把 `%TEMP%\xxx` 当作唯一证据来源**。依据：27 份 handoff 全部如此，复核时只能验证机器可复跑的数字。
6. **文档一致性门禁（规则 17）** — `.githooks/` 的检查随 pre-commit 运行（docs-only 提交也跑，不启 Maven）：引用真实存在、例数与实跑一致、勾选与正文一致、前端基线未突破。红灯改文档或进白名单，不改规则、不绕过。

## 两条 AGENTS.md 事实订正（同批复核发现）

- **`backend/docs/deploy` 不在版本控制内**：该目录被 `backend/.gitignore:23` 的 `docs/` 规则排除，`git ls-files` 为空，而 AGENTS.md 与多条任务都指向它。磁盘上那份 `nginx-security.conf` 只是早先安全响应头片段，**不含**助手 SSE 所需的 `proxy_buffering off` / `proxy_read_timeout`。已在 AGENTS.md 就地注明。
- **前端门禁口径与事实不符**：原文写"以 type-check + lint 作为检查手段"，而实测有 **124 例**存量错误。改为"改动不得净增"并配基线文件（`frontend/type-check-baseline.txt`），使"净增 0"这句话可被独立复核。
