## 决定

**档 1 端点鉴权定为 A：服务间 API key**（用户拍板）：图库助手 headless 端点只认 `X-Internal-Api-Key`，`app.huoshan.headless-api-key` 为空时**一律拒绝**（fail-closed），比对用 `MessageDigest.isEqual`；用户身份靠代理透传的 satoken 由图库服务端判 RBAC，引擎**不**装 sa-token、不共享 Redis。另：图库助手会话**不建 conversation 行**（`V1__init.sql:26` 外键 `fk_conversation_user` 指向引擎 `user` 表，外部身份插不进去），多轮记忆由无外键的 `chat_message`/`chat_summary` 按 conversationId 承载；会话 id 由 `UUID.nameUUIDFromBytes("huoshan:<userId>:<chatId>")` 派生（定长 36 且跨用户不可读，直接拼接会长达 77 字符超 varchar(64)）

## 理由

备选 B（引擎装 sa-token SB3 直读图库 Redis 会话）实测成本：引擎是独立 Maven 应用、拿不到 backend 的 `StpKit.SPACE`（只能复制 `new StpLogic("space")` 口径）＋ sa-token 与 jackson 序列化器需与 backend 版本锁步＋引擎自身 spring-session 也占 Redis（库位要对齐，本地仓还没有 SB3 版 starter 需联网下载）＋端点将对"任何已登录用户"开放（绕过后端代理、无限流无审计，安全全押网络隔离），与设计文档 L94/L110「只接受服务间 API key、不注册登录体系」相悖；备选 C（引擎回调图库校验 token）受限于 `/user/get/login` 走的是 Spring Session 而非 sa-token（`UserServiceImpl.java:209-221`），需另加接口
