## 决定

**AI 打标立项与落地口径（T15；用户拍板：只管理员手动触发、两步式、普通用户助手摘掉只读打标）**：① 打标能力放**图库 backend**——新增 `api/vision/AiVisionTagApi`（OpenAI 兼容看图）+ `manager/ai/PictureAiTagManager`（提示词 / 有界并发 / 单张独立计时 / 容错解析 / 清洗 / `applyTo`）+ `PictureServiceImpl#suggestAiTags/#applyAiTags` + `PictureController` 两个 `@AuthCheck(mustRole = ADMIN)` 端点 + 配置 `app.ai.vision.*`（密钥不入库）；**不做定时任务/阈值自动触发**、**不新增 `ai_tag_*` 数据列**、不做每日配额；② 流程**两步式**：先出建议（只读、零写库）→ 管理员确认后 `apply` 落库；③ **只写 `tags` 与 `category`**，审核状态/审核人/审核留言/审核时间**结构性不可能被写到**；④ 词表 `usageCount` 按批去重各计一次；⑤ 并发采用同日定下的"层次一"（每请求独立有界池 4 + 单张 45s 独立计时 + 单张失败不连坐 + 结果按输入顺序落位），单次上限 8 张（与引擎 visionTagger 同口径）。

## 理由

**为什么必须在图库侧（读代码实测）**：公共图库的图 `spaceId IS NULL`，助手唯一的写标签工具走的 `/picture/edit/batch` **按 `spaceId` 查图且强制空间属主**（`PictureServiceImpl:1145-1154`）⇒ 覆盖不到；而单张 `editPicture`（`:921`）会调 `fillReviewParams`（`:587-599`）⇒ 非管理员身份打标会把图**打回待审核**（于是从公共图库消失）、管理员身份打标会把 `reviewerId`/`reviewMessage` 覆盖成"管理员自动过审"。**为什么两步式**：公共图库是访客门面，写错标签影响面大于空间图；且"建议—确认"本就是设计文档 L58 的口径（对话场景由用户确认、管理端由管理员确认，两者不冲突）。**为什么不需要系统身份或长期凭据**：定时触发被否掉后，管理员手动触发天然带自己的登录态，既不用给引擎开系统写通道，也不用凭据驻留。**未做**：前端入口（T16）、助手侧工具裁剪（T17）。门禁 backend 48 → **70 例**绿（新增 22）；集成测试在真库逐字段核对审核四字段不变、`usageCount` 各 +1、出建议零写库。讲解见 `docs/features/F14-AI打标.md`。
