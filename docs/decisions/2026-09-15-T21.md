## 决定

**T21 收口 T8-hard review 遗留的三条 P3**：① `BaseAgent.runLoop` 尾部的上限提示加前置条件 `state == RUNNING`——**用户可见的行为修正**（回答气泡不再多一句"执行结束：达到最大步骤 (N)"）；② `AgentEvent.Error` javadoc 由"且是本轮唯一的事件"改为"**替代回答帧**、是本轮**最后**一条业务事件"，并写明"只有第一步就失败时才是唯一事件"；③ 计划 Task 3 的设计偏差入档（未新建 `AgentExecutionException`、失败置 `state=ERROR` 而非 `FINISHED`），"一个 agent 实例只跑一次"的不变量整段提到 `BaseAgent` 类注释。

## 理由

**为什么这么修**：① 循环的两个退出条件（`state != FINISHED` 与 `currentStep < maxSteps`）会**同时成立**，所以必须判状态——"到步数"本身不等于"没答完"；**选"文档对齐代码"而非反之**，是因为 `state=ERROR` 有承载：`cleanUp()` 故意不复位 `ERROR`（`ToolCallAgent.cleanUp()`），退回 `FINISHED` 会让"失败过的实例"在语义上变成"正常收尾"；② 中途失败本就要让消费端处理"有过程/有回答、随后报错"，措辞过强会误导后来者写错断言；③ 不变量写明"**不被入口守卫强制**"（`runLoop` 只要求 `IDLE`，已跑完一次的实例技术上能再跑、只是 `messageList` 会带上一轮会话），免得被当成代码保证。**红绿实测**：两条新契约测试修复前必红，逐字输出 `expected: "final-answer"` / `but was: "final-answer` + 换行 + `执行结束：达到最大步骤 (1)"`；**负向控制**：修复后摘掉 `state == RUNNING` 重跑，恰好这两条红、同类其余 13 例绿。**门禁**：`ai/agent` 156 → **159 例**、backend 74 例绿；提交 `e4f09a5`。
