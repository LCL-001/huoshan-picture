## 决定

**T22：MCP 降级改为用户可见提示 + 前端社交残留清理 + F11 勾选时机确定（用户拍板）**：① **反转 T19 的"静默降级"决定**——降级时在本轮开头发一条 `notice` 帧（文案"图片搜索服务暂时不可用，本轮对话无法帮你搜图（其它能力不受影响）"），前端渲染成回答上方一行弱化文本；② 前端**只保留通知**：删掉停用的帖子/社交三页与三路由，`postController.ts` 整体删除（6 个通知函数先迁入 `api/notificationController.ts`）；③ **F11 勾选时机 = 等一期部署上线后**（代码已到 T22，尚未上线，故 spec 里仍留 `[ ]`）。

## 理由

**为什么改口（T19 → T22）**：T19 选静默降级是为了"少一个工具照常开对话"，但真用起来用户体感是"模型答不了搜图、不知道是自己问错了还是服务坏了"——**降级本身没错，"不说"才是问题**；文案刻意不提 "MCP"（用户认不出这个词），也不带失败原因与地址（那是日志的事）。**为什么"Bean 不存在"不提示**：那是配置选择（`AI_MCP_CLIENT_ENABLED=false` 等），不是故障，报"服务不可用"反而是假消息 ⇒ `resolve` 返回 `McpTools(callbacks, degraded)` 把两种"没工具"分开。**为什么通知要迁文件而不是留个剩通知的 `postController.ts`**：该文件是"生成产物 + 手写函数"混装，整个删掉能避免下次误重跑生成器把手写部分覆盖掉（机制见 `plan.md` 存量遗留与同日相关记录）。**验证**：`ai/agent` 159 → **164 例**、backend 74 例绿；前端 `type-check` 124（与改动前持平）、改动文件 eslint 0 新增错。**边界**：降级提示的**浏览器人工验收未做**（只过静态检查与帧级契约）；提示只在"本轮开头"发，"中途才发现降级"覆盖不到；**没让模型知道**降级（提示词未改）。
