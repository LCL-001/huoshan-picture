## 决定

**前端 API 客户端不跑生成器：新接口一律按现有风格手写进 `api/*.ts`（T16 实测）**：执行 `npm run openapi`（`@umijs/openapi` 指向 `http://localhost:8123/api/v2/api-docs`）会把 `frontend/src/api/` **全量改名**——按 `@Api(tags)` 的中文名生成 `tupianxiangguanjiekou.ts` / `yonghuxiangguanjiekou.ts` 等，**删掉**仓里现有英文命名的 `pictureController.ts` / `userController.ts` 等，还会删掉**手写**的 `assistantController.ts`（取票与拼流地址）与 `authCaptcha.ts`，全站 `@/api/*.ts` 导入会集体失效。**机制（读 `@umijs/openapi/dist/serviceGenerator.js`）**：① 文件名取 operation 的 `tags[0]`（`:224`），经 `resolveTypeName` 处理——名字里含 CJK（`[\u3220-\uFA29]`，覆盖中文）就转 `tiny-pinyin`（`:58-62`）⇒ `图片相关接口` → `tupianxiangguanjiekou.ts`；② `genFile()` 生成前先 `glob.sync('./src/api/**/*')` 逐个 `rimraf`（`:277-284`），**整目录清空**再生成——手写文件在同目录必死（`projectName` 默认就是 `api`，`:239`）；③ 脚本要求**后端在跑**（`schemaPath` 指向 localhost:8123 的 api-docs），后端没起时它反而会报错退出、不会破坏文件——本仓从未重跑过它（`git log -- frontend/src/api/` 只有初始化 `cc6fd6f`、手写 `assistantController` 的 `6d6e4f2`、改它的 `af2995f`），现有英文名文件是**原项目的冻结产物**，而 AGENTS.md 里写着这条命令。

## 理由

仓里现有 `api/*.ts` 是**另一次生成/整理**的产物（英文 controller 命名），与当前生成器配置不兼容。**做法**：新增接口手写进对应 `xxxController.ts`（并往 `typings.d.ts` 补 `BaseResponseXxx_` 与 DTO/VO 类型，雪花 id 按 `string` 声明——后端 `JsonConfig` 把 Long 序列化成字符串，按 number 会丢精度）。**不要执行 `npm run openapi`**。**将来若要恢复生成器**：官方扩展点是 `hookCustomFileNames`（`:258`，可自定义文件名）+ 把 `projectName` 指到独立目录（如 `src/api/generated`）让手写文件留在外面，作为独立任务做（规则 3）。**证据**：T16 实测生成后 12 改 + 9 增（`assistantController.ts`、`authCaptcha.ts` 被删），已 `git checkout` 全量还原；手写方案的 `type-check` 净增 0（138 → 138）、新组件 eslint 干净。
