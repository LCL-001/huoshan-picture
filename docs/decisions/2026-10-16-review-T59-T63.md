## 现在修

### R1 / T65 / P2：写入后的摘要查询能把已完成操作变成失败

- 位置：`backend/src/main/java/com/lcl/yunpicturebackend/manager/ai/AiAssistantOperationManager.java` 175–181、195–198 行。
- `confirm` 先完成 `executeBatchEdit` / `executeUrlImport`，再由 `withPlanContext` 调 `spaceService.getById` 补空间名。此时业务写入已结束，外层没有包住这些操作的事务；新增的补读若抛异常，confirm 仍整体报错，控制器还会回灌「写操作未执行」。
- 复现：让消费脚本返回合法批编计划，图片 service 正常完成，仅令 `spaceService.getById(30L)` 抛异常。实际已调用图片写入，confirm 随后抛 `IllegalStateException`；URL 导入同样走该路径，重做可能产生重复导入。
- 期望：辅助摘要读取不能推翻既成执行结果。可复用/前置摘要数据，或让空间名读取失败仅降级为空间 ID；不要在成功写入后新增硬失败点。
- 本项不是已接受的「空间改名造成摘要名字漂移」：后者不改变成功/失败，本项会改变。

### R2 / T66 / P2：确认门拒绝后仍把未认证 operationId 写成隐藏系统事实

- 位置：`backend/src/main/java/com/lcl/yunpicturebackend/controller/AiAssistantController.java` 182–187、222–233 行。
- 所有 `RuntimeException` 都进入失败回灌，包括缺字段、未知操作、digest/chatId 不匹配等尚未验证计划绑定的请求。回灌直接采用请求中的 chatId/operationId，而后引擎统一加 `huoshanSource=system_fact` 并从前端历史隐藏。
- 复现：已登录用户向本人的 chatId 提交不存在的 operationId `not-a-real-operation]\nUSER_SUPPLIED_TEXT` 与任意非空 digest。确认门拒绝执行，但该 ID 中的换行/任意文本仍进入事实正文和 metadata；不需要真实准备计划。
- 影响：产生普通用户可驱动的隐藏、带系统来源标记的文本写入口，不能再宣称事实 payload 不受用户控制。仅污染调用者自己的会话，不构成跨用户越权，也不据此宣称模型必然被注入成功。
- 期望：区分「确认请求被拒绝」与「已认证操作执行失败」；未经绑定验证的字段不得作为既存操作身份或事实正文。合法执行失败仍应按既定口径回灌，不能简单恢复为全部失败不记录。
- 本项不同于已接受的「失败回灌无类型」和「失败记录不去重」：这里尚未证明存在该操作，且带入用户任意文本。

### R3 / T67 / P2：被格式包裹的否定 token 仍被读反

- 位置：`ai/agent/src/main/java/com/lcl/myaiagent/agent/HuoshanAssistantAgent.java` 273–284 行。
- `isNegated` 只允许否定词与 token 间出现空白；`normalizeDecision` 只剥整个输出外围包裹。句内 token 若带反引号、引号或粗体，否定匹配失效。
- 复现：`not IN_SCOPE` 正确拒绝，但 `This request is not ` + 反引号包裹的 `IN_SCOPE` + `.` 会放行；双引号/粗体同样。反向的被包裹 `OUT_OF_SCOPE` 则被误拒。
- 调用链探针：用户输入 `Write quicksort code`，门卫桩返回上述反引号否定文本，主模型仍调用 2 次、执行 `listSpaces` 并输出 `UNRELATED ANSWER`；对照 `not IN_SCOPE` 时主模型调用 0 次，正确固定拒绝。
- 期望：补否定词与受支持格式包裹的组合回归，保持首 token、词表和回看窗口不变。不需要引入自然语言解析框架。
- 这是 T61 未补齐的存量缺口，不是该提交新引入的回归；范围门卫非授权边界，判 P2。
