# 2026-09-15 — D1 收口：引擎与 MCP 只监听回环 + 文件工具路径校验

> 详情文件：自 `docs/decisions.md` 引用。口径以 `decisions.md` 表内那一行为准。

## 决定

用户 2026-09-15 批准（答"开始"），按以下方式收口 **D1**——即复核把"引擎无鉴权旧端点"从一句挂账升级为**部署前硬阻断**的那条：

1. **引擎与 MCP 服务只监听回环**：`server.address: 127.0.0.1`，写进**入库的** `application.yaml`；
2. **`FileOperationTool` 补路径校验**：模型给的文件名解析后必须仍落在工具目录内，越界即拒；
3. **不给 `/ai/manus/**` 加鉴权**——这是本决定与"加鉴权"方案的关键分歧点，理由见下。

## 为什么用网络隔离而不是加鉴权

`/ai/manus/chat` 零鉴权，而它挂的 `FileOperationTool` 对 `fileName` 不做清洗、`message`（=提示词）由调用者控制 ⇒ 构成**未授权的任意文件读写**（受进程文件权限约束），另有抓取类工具的 SSRF 面。给端点补 key 看似直接，实测不可行：该端点服务的是**冻结的 MyManus 前端**，浏览器发不了自定义头，加 `X-Internal-Api-Key` 会把那个前端打死。

而部署拓扑本来就不需要它对外可达——图库后端代理打的是默认值 `http://localhost:8124/api`（`AiAssistantProxyManager`），浏览器只与 8123 说话。所以**一行 `server.address` 让整族旧端点对外不可达**，比逐个端点补鉴权更彻底、更便宜，且不改任何端点行为。

**写在入库文件里**是这次的一个要点：`application-prod.yaml` 不入库，改动会绕开 review 且新克隆看不到；而 `application.yaml` 入库，故该修复**可被 review、且对 prod 生效**（prod 那份没有覆盖 `server.address`）。

## 影响面（代价写清楚，不粉饰）

| 项 | 变化 |
|---|---|
| 引擎（8124）、MCP（8127） | 只监听 127.0.0.1，主机外不可达；**同机链路（backend → 引擎 → MCP）零影响** |
| `/ai/manus/**` 一族旧端点 | 零鉴权问题**随之不可达**——注意这是"没有攻击面"，**不是"修好了鉴权"** |
| 冻结的 MyManus 前端 | **失去远程访问**（有意如此）。若将来要保留，替代做法是在引擎前加只允许内网的防火墙规则并覆盖 `server.address` |
| **D2：引擎 `CorsConfig`（`allowCredentials(true)` + `allowedOriginPatterns("*")`）** | **缓解、未修**。回环绑定后远程浏览器够不到它，但**本机上的任何进程/页面仍可利用**。记为 mitigated, not fixed，**不当作已修好** |
| 抓取类工具的 SSRF 面 | **不修**：与 D2 同属"缓解未修"，回环后不可达 |
| 容器化部署 | 容器内绑 127.0.0.1 无法被端口映射访问；届时应显式覆盖该项（已写进配置注释） |

## 覆盖范围的一处扩大（单独标明，可单独回退）

起草时发现 **MCP 服务（8127）是完全同形的暴露**：同样按"只被同机引擎调用"部署、同样没有鉴权，而它内部握着 Pexels API key——公网可达即等于把配额开放给任何人。故**一并绑回环**（`ai/image-search-mcp-server/src/main/resources/application.yaml`，一行）。

用户批准的范围是"D1（引擎）"，这一行是据同一理由扩的。**不同意可单独回退这一处，不影响引擎那两处**——三处改动互相独立。

## 验证方式（规则 12）

- **新增纯单测** `FileOperationToolPathGuardTest`：零文件 I/O（因此不会把 `ai/agent/tmp/` 写进工作区，也不依赖 MySQL/Redis），`../` 穿越、多级穿越、绝对路径（Windows 盘符与 root-relative）全部被拒；正常文件名与子目录名放行。放行一侧用"**错误信息里不含越界标记**"来断言，避免为了断言而真写文件。
- **负向控制**：摘掉守卫 → 该用例红（证明不是空转）。
- **门禁覆盖**：新测试类不在 `.githooks/pre-commit` 的排除名单里，**须实测它确实进了门禁运行**（看 `Tests run` 计数与类名）。
- **不破坏既有链路**：代理默认引擎地址即 `http://localhost:8124/api`，回环绑定后仍可达；引擎与 MCP 的真机冒烟记录见 `docs/plans/records/`。

## 未做（明确不做，不是遗漏）

- 不给 `/ai/manus/chat` 加鉴权（见上）
- 不修引擎 `CorsConfig`（缓解已足够；改动会牵连冻结前端）
- 不修抓取类工具的 SSRF（回环后不可达）
- 不动 MCP 的 `request-timeout` 与工具面
- 不改引擎端口、context-path、会话 Cookie 名等既有口径
