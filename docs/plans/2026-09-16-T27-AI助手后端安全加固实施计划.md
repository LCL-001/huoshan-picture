# T27 AI 助手后端安全加固实施计划

> **状态：第一阶段前 4 项已于 2026-09-16 完成。** T27.1、临时摘写工具、日志/异常脱敏和页面文案同步的实施证据见 `docs/plans/records/T27-first-release.md`；T27 整体仍未完成，取消竞态、错误体有界读取与完整确定性写确认门继续保留。
> **执行入口：** 新会话先读 `AGENTS.md`、`docs/spec.md` 关键三行、最新 handoff，再读本文；每个子任务严格执行“复现测试先红 → 修复到绿 → 单独 commit”。

**目标：** 收口 2026-09-16 对 AI 助手后端完整链路 review 发现的凭据泄露、取消竞态、内部信息外泄和“模型可直接触发写工具”四类风险；保持现有登录态、RBAC、一次性 chat ticket 和只读工具行为不变。

**范围：** `backend/` 的 AI 助手 controller / ticket / SSE proxy，`ai/agent/` 的图库工具、日志与事件协议，以及确定性写确认所需的最小前端交互。

**不做：** 不顺手处理已关闭的 P3/已知限制（GET message 进入访问日志、多行 SSE、缺 `[DONE]`、线程池拒绝空 500、300 秒超时竞态、chatId 长度/日志换行、ticket 频控等）；不新增进程、依赖或数据表；不修改非助手业务接口的既有交互；不把“范围门卫”当权限边界。

## 一、已确认的缺陷与处置

| 编号 | 严重度 | 缺陷 | 本计划处置 |
|---|---:|---|---|
| R1 | P1 | `HttpURLConnection` 默认跟随重定向，可能把内部 API Key 与用户 satoken 发往重定向目标 | 禁止自动重定向；3xx 一律失败；增加跨主机负向测试 |
| R2 | P1 | `batchEditPictures` / `batchUploadByUrl` 仅靠提示词约束，模型调用即真实写入 | 建立后端持有、一次性、绑定操作摘要的确定性确认门；无确认时执行层零写入 |
| R3 | P2 | 长期 satoken 可从 query 参数读取 | 删除 query 回退，只认请求头或 HttpOnly Cookie |
| R4 | P2 | 浏览器在 `upstream.set` 前断开时，worker 仍可能建连并继续整轮 | 增加原子取消状态，覆盖取消早于/晚于连接赋值两种时序 |
| R5 | P2 | 引擎 Prompt、工具参数和工具结果以 INFO 原文落日志 | 改为结构化元数据日志，用户内容默认不落日志；换行不得伪造日志行 |
| R6 | P2 | 代理 JSON `message`、图库调用异常原文会返回普通用户 | 用户端固定文案/白名单业务错误；原始异常仅服务端受限日志 |
| R7 | P2 | 2048 字符错误体上限可被单个超长行绕过 | 分块有界读取；日志另设截断，不用 `readLine()` 读完整长行 |
| R8 | P2 | Controller 支持自定义凭据名，Proxy 仍硬编码 `satoken` / `SESSION` | 两层共用同一配置源，并用非默认名称做契约测试 |

## 二、实施原则

1. **凭据 fail-closed：** 任何 3xx、名称不一致、缺凭据或来源不合法都不得继续上游请求。
2. **写入不能由模型授权：** LLM 只负责提出操作计划；最终执行必须由用户的确定性确认触发，且执行内容必须等于用户看到的计划。
3. **确认凭据最小能力化：** 单用户、单 chat、单操作摘要、短 TTL、单次消费；不能被模型自行生成，不能跨用户/跨会话/跨操作复用。
4. **原文不跨信任边界：** 用户输入、模型提示、工具参数、工具结果、内部异常和部署细节默认不进 INFO，也不返回浏览器。
5. **不削弱既有授权：** 确认令牌只是“用户意图证明”，不能替代图库端登录态、空间权限和管理员权限。
6. **每项独立提交：** 不把所有修复塞进一笔大提交，便于新会话逐项红绿和回滚。

## 三、任务顺序

### T27.1 代理凭据与重定向加固

**文件范围：**

- `backend/src/main/java/com/lcl/yunpicturebackend/controller/AiAssistantController.java`
- `backend/src/main/java/com/lcl/yunpicturebackend/manager/ai/AiAssistantProxyManager.java`
- `backend/src/main/java/com/lcl/yunpicturebackend/config/AiAssistantProperties.java`（若选择把凭据名收敛到该配置）
- 对应 `backend/src/test/` controller / proxy / integration 测试

**改动：**

1. `HttpURLConnection` 显式 `setInstanceFollowRedirects(false)`；所有 3xx 走通用上游异常，不读取或跟随 `Location`。
2. `resolveSatoken()` 删除 query 参数回退，只保留配置名对应的 header → Cookie。
3. Proxy 不再硬编码 `satoken` / `SESSION`，与 Controller 使用同一配置值。
4. 不在日志中打印敏感请求头、Cookie、完整重定向地址或 token。

**先红测试：**

- 桩引擎返回跨主机 302：代理不得发起第二次请求；攻击者桩收到请求数为 0。
- query 中只有有效 satoken：入口拒绝，且上游请求数为 0。
- 自定义 token/header 与 session Cookie 名：入口能取到，代理也按自定义名称转发。
- 默认配置行为保持兼容。

**验收：** 聚焦测试 + backend 常规无外部依赖门禁全绿；敏感值在测试日志中 0 命中。

**建议 commit：** `fix: 加固助手代理凭据转发`

### T27.2 SSE 取消竞态与错误边界

**文件范围：**

- `backend/src/main/java/com/lcl/yunpicturebackend/manager/ai/AiAssistantProxyManager.java`
- `backend/src/test/java/com/lcl/yunpicturebackend/manager/ai/AiAssistantProxyManagerTest.java`
- 必要的专用测试替身，不触碰其它 manager

**改动：**

1. 增加原子取消状态；`onCompletion` / `onError` / `onTimeout` 统一置取消并关闭连接。
2. worker 在 `open()` 前检查取消；连接创建后使用原子注册，若已取消立即断开，不能进入 `getResponseCode()` / `relay()`。
3. JSON 错误体的原始 `message` 不再直接进入回答气泡。外部统一固定文案；如确需保留业务错误，必须按明确 code 白名单映射，不能按“有 message 就透传”。
4. 错误体改为字符块有界读取，最多保留固定长度；日志同样截断并去除控制字符。

**先红测试：**

- 取消发生在 worker 启动前：`open()` 不得被调用。
- 取消发生在连接创建后、注册前：连接立即断开，relay 不执行。
- 正常路径：只关闭一次且 `[DONE]` 行为不变。
- 500 JSON 含配置名、内部地址或请求头名称：浏览器只收到固定文案。
- 单行超长错误体：保留长度不超过上限，日志内容不包含尾部 marker。

**验收：** 竞态测试循环执行仍稳定；backend 门禁全绿；不改变已记录的多行 SSE / 缺 `[DONE]` 等已知限制。

**建议 commit：** `fix: 收口助手代理取消与错误边界`

### T27.3 引擎日志与工具异常脱敏

**文件范围：**

- `ai/agent/src/main/java/com/lcl/myaiagent/advisors/MyLoggerAdvisor.java`
- `ai/agent/src/main/java/com/lcl/myaiagent/agent/ToolCallAgent.java`
- `ai/agent/src/main/java/com/lcl/myaiagent/tools/huoshan/HuoshanToolSupport.java`
- 对应 `ai/agent/src/test/` 测试

**改动：**

1. INFO 不再记录完整 Prompt、完整模型回答、工具 arguments、工具 responseData。
2. 保留可运维元数据：conversation/trace 标识（若已有）、模型调用耗时、工具名、工具数量、成功/失败码、结果条数；不得记录凭据和用户内容。
3. 若保留 debug 诊断，必须默认关闭，并做长度上限、控制字符转义和敏感字段清洗。
4. `HuoshanToolSupport` 的未知异常对用户只返回固定错误；`e.getMessage()` 仅进入受限服务端日志。
5. 已知业务异常也要审查：只允许公开稳定、无内部细节的业务文案。

**先红测试：**

- 用户消息、图片名、URL、工具参数放置唯一 marker 和换行伪造文本；INFO 捕获器中 marker 为 0，不能产生伪造独立行。
- 图库连接异常包含 `127.0.0.1:8123` 等内部信息；工具返回与 SSE step 中不得出现该地址。
- 日志仍包含工具名、结果码等必要运维字段。

**验收：** `ai/agent` 门禁全绿；真实一次只读会话日志抽查无用户原文、URL、标签和工具返回正文。

**建议 commit：** `fix: 脱敏助手提示词与工具日志`

### T27.4 确定性写确认协议字据

> 这是用户可见行为变更，属于 AGENTS 规则 3。新会话必须先完成本任务并让用户确认，再写 T27.5 以后代码。

**文档范围：**

- `docs/spec.md` 关键三行：补充“写操作必须经过确定性确认门，模型自然语言判断不构成授权”
- `docs/features/F11-AI助手MVP.md`、`docs/features/F12-图库助手档3工具与联调.md`
- 本计划与必要的 decision 记录

**推荐协议：后端持有待执行计划，前端确认后执行精确计划。**

1. 模型只能调用“准备写入”能力，提交规范化操作计划；准备阶段**零写库**。
2. backend 将规范化计划存入 Redis，生成不可猜的 `operationId`，绑定 `userId + chatId + operationType + payloadDigest`，短 TTL。
3. SSE 新增结构化 `confirmation_required` 事件，前端显示用户真正将要执行的目标空间、图片数量、字段变化或 URL 数量。
4. 用户点击“确认执行”后，frontend 调 backend 确认端点；backend 原子消费 operation，并执行 Redis 中保存的原始计划，**不接受前端或模型重新提交一份可变 payload**。
5. 取消、过期、重复确认、换账号、换 chat、摘要不一致全部零写入。
6. backend 执行时仍走既有登录态、空间 RBAC、额度与 URL 上传安全校验；确认不能绕过它们。

**明确不采用：**

- 不把“用户说了确认”交给模型自行判断；
- 不让模型生成或持有可伪造的确认 token；
- 不只在 system prompt 里增加一句“必须确认”；
- 不把确认布尔值作为工具参数（模型可以自行填 true）；
- 不修改普通图库页面调用的通用编辑/上传接口语义。

**验收口径：** 用户确认后的执行内容必须与确认卡片逐字段相同；页面刷新/并发双击/重放最多执行一次。

**建议 commit：** `docs: 确认助手写操作授权协议`

### T27.5 backend 待执行操作与原子确认

**前置：** T27.4 已获用户确认。

**文件范围：**

- `backend/src/main/java/com/lcl/yunpicturebackend/controller/` 下助手专用端点
- `backend/src/main/java/com/lcl/yunpicturebackend/manager/ai/` 下待执行操作 manager
- 必要 DTO、Redis Lua、测试
- 复用既有 picture service/manager；禁止复制一套批量编辑或上传业务逻辑

**实现要求：**

- Redis key 与现有 ticket 隔离；短 TTL、随机 operationId、值中保存规范化计划和 digest。
- prepare 只存计划不写数据；confirm 原子校验并单次消费。
- 执行使用服务端保存的计划；前端确认请求只携带 operationId，不携带可替换业务 payload。
- 绑定当前用户和 chat；失败不泄露 operation 是否属于别人。
- 并发确认恰好一个成功执行，其余返回“已处理或已过期”。
- 执行结果返回可展示的结构化摘要，不返回内部异常原文。

**先红测试：** 无确认、伪造、过期、别人的 operationId、不同 chat、重放、双并发、篡改 digest、RBAC 失败、额度失败全部零写入；正向恰好一次写入。

### T27.8 联调、独立 review 与文档收口

**联调正向：**

- 标签整理：准备计划 → 卡片内容核对 → 确认 → 只修改卡片列出的字段。

**门禁：** backend 常规测试、`ai/agent` 门禁、前端助手 format/copy 检查、type-check 基线核对、改动文件 eslint。

**文档：** 更新 F11/F12/F13（若新增 SSE 事件）、任务 record、decisions；按规则 13 建议再开独立只读 review，只判“现在修 / 已知限制并关闭”。

**建议 commit：** 代码不再混入；收口文档使用 `docs:` 单独提交。

## 五、停止条件

- 连续两轮无法把同一复现测试修绿：按逃生舱规则停止并汇报。
- 发现必须修改普通图库编辑/上传接口语义、引入新表/依赖/进程：停止，先更新字据并等用户确认。
- 无法保证“确认卡片内容 = 最终执行内容”：不得上线写工具；宁可临时摘掉写工具。
- 任何测试或日志出现真实 token、Cookie、内部 API Key：立即停止，清理证据文件并按密钥事件处理。
