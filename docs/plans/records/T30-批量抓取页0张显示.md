# T30 — 批量抓取页"0 张"显示修正

> 任务条目见 `docs/plan.md` T30。功能讲解见 `docs/features/F3-批量抓取.md`。本记录只保存实施过程与可复跑证据。

## 问题（本任务由"这个功能完善了吗"的复核发现）

`AddPictureBatchPage.vue` 判的是 `res.data.code === 0 && res.data.data`。后端成功抓取但**一张都没入库**时返回 `{code: 0, data: 0, message: "ok"}`（`message` 由 `BaseResponse.success` 固定为 `"ok"`），而 JS 里 `0` 是 falsy ⇒ 走失败分支 ⇒ 页面显示 **标题"任务执行失败"、描述"ok"**。

这个 bug 在 T29 之前就存在，但那时"0 张"罕见（冷门搜索词/全部下载失败）；T29 起"重跑同一搜索词"**稳定返回 0**，它从罕见变成最容易碰到的路径。属规则 13 的"现在修（廉价且用户可见）"。

## 改动

- 新增纯函数 `frontend/src/utils/batchCrawlResult.ts`：`mapBatchCrawlResponse(response)` → `{status, title, desc}`，四种状态 `success / empty / error`（页面的 `background` 由超时分支产生，不进纯函数）。判的是 `code === 0` 而不是 `code === 0 && data`。
- 新增常驻断言 `frontend/scripts/check-batch-crawl-result.mjs` + `npm run check:batch-crawl-result`：前端没有测试框架，沿用 `check:assistant-format` 的做法（esbuild 转译**真的** `.ts` 后在 node 里断言）。9 组用例，覆盖 0 张、1/30 张、成功但缺数量、业务码非 0、错误缺 message、状态值域。
- `AddPictureBatchPage.vue`：接上纯函数；新增 `empty` 状态（`InfoCircleOutlined` + 蓝色 `.result-icon.empty`）与文案"没有新增图片：结果可能都已导入过，或该搜索词没有可用图片。换个搜索词、或调整偏移量后再试。"；`icon` 与 `STATUS_ICONS` 用 Vue 的 `Component` 类型（顺带收掉该文件两处 `no-explicit-any`，改动文件 lint 净减）。
- `package.json`：新增 `check:batch-crawl-result` 脚本。

## 先红后绿

先把纯函数按**线上现有语义**写出来（`code === 0 && data`），再让断言脚本按正确语义断言：

```
cd frontend && node scripts/check-batch-crawl-result.mjs
FAIL zero pictures is not an error
  expected: "empty"
  actual:   "error"
FAIL zero pictures keeps the completion title
FAIL zero pictures explains itself instead of leaking the raw message
FAIL success with no count is empty, not error
FAIL success with undefined data is empty

```

修复纯函数后：

```
cd frontend && npm run check:batch-crawl-result
RESULT: PASS (batch crawl result)
```

第 2 次**没有**出现修复前的「任务执行失败 / ok」——T30 的浏览器路径（含 axios 装配那一层）由此闭环，这正是 review 说"前端断言只覆盖纯函数、不覆盖装配"时缺的那一环。

**可复跑的旁证（同一会话补做，只读 SQL）**

```sql
SELECT COUNT(*) FROM picture WHERE sourceUrl IS NOT NULL AND isDelete=0;              -- 3
SELECT id, spaceId, LEFT(sourceUrl,60), picSize, reviewStatus, createTime
  FROM picture WHERE sourceUrl IS NOT NULL AND isDelete=0 ORDER BY createTime DESC;   -- 见下
```

三条记录：`spaceId` 全为 `NULL`（批量一律进公共图库）、`reviewStatus=1`（管理员自动过审）、`picSize` 94~143KB（真实下载）、`createTime` 落在**同一秒**（印证 T28 的一次批量入库）、`sourceUrl` 是真实图源（`https://pic.nximg.cn/file/...`，与搜索词「猫」相符）。**该旁证只在这三行存在期间可复跑**（用户删图后即失效），删除后以本表的截图事实为准。
