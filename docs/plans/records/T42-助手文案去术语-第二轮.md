## 交付

- **引擎回答气泡里三句系统话术**（`BaseAgent`，都在"助手自己说话"的位置，用户直接看到）：
  - `检测到循环，智能体已终止` → **`助手重复了同样的步骤，已停止本次回答`**；
  - `执行结束：达到最大步骤 (N)` → **`这次回答达到步数上限（N 步）`**；
  - `错误：无法从该状态运行代理：RUNNING` → **`助手正忙，请稍后再试`**（不再往外抛状态机枚举值）；`错误：用户提示不能为空。` → **`这条消息是空的，请重新输入`**。
- **后端代理给浏览器看的错误帧**（`AiAssistantProxyManager`）：`图库助手引擎暂时不可用…` → **`助手暂时不可用，请稍后重试`**；`图库助手引擎拒绝了本次请求：` → **`助手未能处理本次请求：`**；`…引擎响应异常（HTTP 502）` → **`助手响应异常（错误码 502）`**；读历史失败的 `引擎暂时不可用` → `助手暂时不可用`（用户侧看不到，一致性改）。
- **登录门槛的错误文案**（`AiAssistantController`）：三条都去掉了 `satoken`/`Cookie` 细节——`登录态不完整（缺少 satoken）` → **`登录信息不完整，请重新登录`**；`登录态已失效（satoken 无效或已过期）` → **`登录已过期，请重新登录`**；`登录态不一致（satoken 与会话不属于同一账号）` → **`登录信息不一致，请重新登录`**。这些会出现在确认卡片的失败行上。
- **前端取票失败文案**：`助手暂时不可用（未能取得本次对话凭据），请稍后重试` → **`助手暂时不可用，请刷新页面后重试`**；`assistantController` 的兜底文案 → `未能开始本次对话，请刷新页面后重试`（并把前者作为**期望文案**钉进 `check:assistant-copy`）。
- **写操作准备端点的参数错**（`AiAssistantOperationManager`，会回给模型、可能被转述）：`chatId 不能为空` → `会话标识不能为空`；`plan 不能为空` → `缺少操作计划`；`缺少图片 id 列表` → `缺少要修改的图片`。

## 审计结论：其余命中为什么不改

用"提取用户可见字符串 + 术语关键词"扫了前端 8 个文件、引擎 11 个、后端 4 个（方法见 handoff 0033 同日续四），剩下的命中分三类：

1. **卡片摘要仍显示"目标空间 id：2102416518058352643"** —— 这不是改词能解决的：要让用户认得出空间，得由后端把**空间名**放进摘要（顺带核对该空间属于调用者），即 T27.10 那件事，**待用户批准 + 字据**。本轮把这条列为**剩余最大的一项**。
2. **刻意保留的内部措辞**：工具参数描述（`空间 id（字符串，原样复制 listSpaces 返回的 items[].id）`）与工具错误（`缺少 spaceId：先调 listSpaces 取空间 id`）——它们面向模型，且卡片/步骤的「详情」本来就是"原始载荷"调试面（T11.1 口径）。
3. **日志与非用户面**：`图库工具调用异常`、`AI 助手转发线程池已满…`、`引擎地址/密钥未配置`（只在部署残缺时抛出，到不了用户）、`@ApiOperation` 注解文案（Knife4j 文档）、`StepTimeline` 的"执行步骤（N 步）"（已是用户词汇）。
