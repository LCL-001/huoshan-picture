# T27.10 实施记录 — 确认卡片摘要改由后端生成（2026-10-01）

> 依据：`docs/decisions/2026-09-29-review-write-gate.md` ①-2（P2-2）；字据 commit `07fc36d`（用户 2026-10-01 批准，N=5）。
> 本文写一次不再编辑；勘误按工作流规则处理。

## 改动

- **backend**：`AiOperationPrepareVO` 新增 `summary`（List&lt;String&gt;，卡片逐行摘要）；`AiAssistantOperationManager` 注入 `ISpaceService`，`prepare()` 在归一化后调用 `buildSummary(plan, 空间名)` 生成摘要——
  - 空间行：查得到给名字（`目标空间：<名>（id：<id>）`），查不到回退 `目标空间 id：<id>`（prepare 仍不做 RBAC、仍零写库，只多一次空间读查询）；
  - url_import：`图片直链：N 条` + 前 5 条逐条编号行 + 超 5 条时 `…（其余 X 条略）`；
  - batch_edit：`目标图片：N 张（id：<前 5 个顿号连接>[…其余 X 张略]）` + 分类/标签/命名规则行（沿用引擎原格式）。
- **引擎**：`HuoshanToolSupport.pendingConfirmation` 改为从 backend 响应读 `summary` **只透传**，缺 summary/为空一律 fail-closed 抛错（PARAMS_ERROR，"图库后端未返回卡片摘要"）；两个 prepare 工具删除自算摘要代码（batch_edit 的"至少一个字段"本地校验保留并提前）。
- **SSE 与前端零改动**：`SseAgentEventListener` 本就逐字透传 `summary`，前端卡片渲染行数组。

## 红绿与门禁

- backend：新增 5 例摘要测试**先红**（`Tests run: 33, Failures: 5`——恰为新加的 5 例，构造器先行落地、摘要未生成）→ 实现后 **33/33 绿**；全量门禁 **144/144**（CI 同口径）。
- 引擎：桩服务器按操作类型回后端摘要 + 两例严格透传断言 + 一例"后端缺 summary 必须报错"**先红 3**（旧代码仍自算）→ 实现后 **8/8 绿**；全量门禁 **208/208**（T43 后为 214）。
- 提交门禁（pre-commit）backend + 引擎全绿（commit `c392ecc`）。
- **真机（与 T43 同一次冒烟，`docs/evidence/2026-10-01-t43-gate-probe.mjs`）**：URL 导入请求直达 `confirmation_required`，卡片摘要即后端生成格式：`目标空间：smoke-t43-space（id：2102416518058352645）` / `图片直链：1 条` / `1. https://…`。

## 负向控制（均实测红）

- backend：删掉 `resolveSpaceName` 的空间查询 → 空间名两条摘要测试红；
- 引擎：把 `pendingConfirmation` 改回自算（或去掉缺 summary 抛错）→ 透传 `containsExactly` 与 fail-closed 两类红。

## 边界与已知代价

- 部署顺序：backend 必须先于引擎（旧 backend 响应无 summary，新引擎 fail-closed 报错——错误文案已说明"版本可能不一致"）。
- 摘要随 VO 返回、不落库：与 review 已知限制 ② 的"顺带收敛"一致（卡片 = 计划同源由构造保证）。
