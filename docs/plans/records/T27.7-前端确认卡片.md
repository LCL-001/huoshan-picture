## 交付

- **SSE 分流**（`assistantSse.ts`）：`AssistantTurn` 增加 `confirmations`（只在实时流出现，历史回放不重建）；新增纯函数 `parseAssistantConfirmation`——形状校验（event=confirmation_required 且 operationId/digest 齐全、summary 是数组）不满足一律返回 null，卡片只因完整合法的确认载荷而出现；`AssistantStreamHandlers` 增可选 `onConfirmation`。
- **确认端点**（`assistantController.ts`）：`confirmAssistantOperation(operationId, chatId, digest)` ——请求**只携带卡片展示过的三项凭据，无任何业务 payload**；实际执行的是后端保存的原始计划，digest 钉死"确认内容 = 执行内容"。自带 `code !== 0` 校验（fetchAssistantTicket 同款），后端用户安全文案原样上抛。
- **卡片渲染与状态簿记**（`AssistantPage.vue`）：卡片出现在过程步之后、回答之前（标题 + summary 行 + 按钮）；状态机 pending → confirming（按钮 loading，双击/重放被状态挡住）→ done / cancelled / failed，状态按 operationId 簿记，结果行与失败原因就地展示。取消为纯客户端行为（不发请求，未确认的操作由后端 TTL 过期作废）。页头文案从"只提供查询和建议"改为"生成待确认操作——你确认后才会执行"。
- **展示纯函数**（`assistantFormat.ts`）：`assistantConfirmationTitle`（类型 → 卡片标题）、`describeAssistantOperationResult`（结果 → 展示行；batch_edit 如实说"已提交 N 张"不承诺逐张、url_import 上报成功/未成功条数，失败原因取后端文案最多 5 条）；prepare 工具的步骤摘要固定"已生成待确认操作（未改动数据）"。**旧写工具名标签保留**——2026-09-13~16 的历史会话步骤回放还要用。
- **常驻断言**（`check-assistant-format.mjs`）：脚本重构为可加载多个 util 文件，新增 10 条断言（帧解析四拒一收、标题映射、结果行三种形态与 5 条截断）。
