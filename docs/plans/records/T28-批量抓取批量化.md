# T28 — 批量抓取落库批量化

> 任务条目见 `docs/plan.md` T28。口径见 `docs/decisions/2026-09-18-batch-crawl-persist.md`；功能讲解见 `docs/features/F3-批量抓取.md`。本记录只保存实施过程与可复跑证据。

## 放行范围（用户 2026-09-18 批准）

1. 并行阶段只做"下载 + COS 转存 + 构造未落库记录"，`CompletableFuture.allOf` 之后一次 `saveBatch`、一次清缓存；
2. URL 检查提到并行前（一次 `IN` 查询 + 批内按源地址去重）；
3. 批量入库失败按引用计数补偿删除已转存的 COS 对象；
4. **接受的代价**：入库阶段由"逐张原子"变为"整批原子"——下载/COS 失败仍逐张跳过，但入库失败整批回滚并报错；
5. `rewriteBatchedStatements=true` 只加本地（`application.yaml`）与模板注释，`application-prod.yaml` 不动，prod 随下次发布生效。

## 改动

- `PictureServiceImpl`：抽出两个 `protected` 测试缝——`fetchBingSearchPage`（内联的 Jsoup 抓页）与 `preparePicture`（下载 + COS + 构造记录，单张上传与批量共用；`uploadPicture` = `preparePicture` + 落库，行为不变）；新增 `filterDuplicateAndMissingUrls`（一次 `IN` 查询 + 批内去重，保留原始序号）与 `persistPicturesInBatch`（一个事务 `saveBatch` + 失败补偿）；`UploadResult.pictureId` → `UploadResult.picture`（未落库记录）。
- `application.yaml`：本地/默认 JDBC URL 加 `rewriteBatchedStatements=true`；`application-local.yaml.example` 注释同步（URL 本体仍只在 `application.yaml` 一处，模板不复制）。
- 新增 `PictureBatchUploadIntegrationTest`（5 用例）。
- 文档：新增 `docs/features/F3-批量抓取.md`（规则 9 要求先有讲解，本次先补写改动前行为再更新为改动后）；`docs/plan.md` T28 字据；`docs/decisions.md` 一行口径。

## 负向控制与回归

- **单张路径未变**：`mvn -B test -Dtest=PictureReplaceQuotaIntegrationTest,PictureReplacePrecheckOwnershipIntegrationTest,PictureReplaceSpaceAuthIntegrationTest,PictureBatchUploadIntegrationTest,SpaceDeleteCascadeIntegrationTest,TagVocabularyIntegrationTest,CacheRebuildLockIntegrationTest -DfailIfNoTests=false` → **Tests run: 24, Failures: 0**。这些用例全部跑在重构后的 `uploadPicture` 上（抽 `preparePicture` 若改了行为，它们会红）。
- **CI 口径（无 MySQL/Redis）**：`mvn -B test -Dtest='!*IntegrationTest,!RedisStringTest,!YunPictureBaseApplicationTests' -DfailIfNoTests=false` → **Tests run: 77, Failures: 0**，与原基线一致。
- **配置项取证**：`batchInsertShouldMergeIntoOneStatement` 用 `SHOW GLOBAL STATUS LIKE 'Com_insert'` 前后差值断言 3 行只算 **1** 条 INSERT（未生效会是 3）。MyBatis 的 StdOut 日志只记每条 `addBatch`，看不出驱动改写后的形态，所以改用服务器计数取证。

## 未验证 / 说明

- **prod 的 `rewriteBatchedStatements` 未生效**：`application-prod.yaml`（不入库）按用户口径未改；下次发布时需同步，否则生产是"一个事务 + N 条 INSERT"（功能正常，只是少一次合并）。
- **真实外网抓取未复跑**：测试替身替换了 `fetchBingSearchPage` 与 `preparePicture`，Bing 改版与 COS 真实链路仍由 `BingImageParserContractTest` 与线上冒烟覆盖，本次没有跑真机抓取。
- **`getByUrl` 对 URL 上传路径实际失效（本任务发现，未修）**：库里 `picture.url` 存的是 COS 地址，而检查传的是源地址，两者不同名空间 ⇒ 单张 `/picture/upload/url` 与批量抓取的"已存在即跳过"都不会命中。本次按规则 1 只保持同口径（合并为一次 `IN` 查询）未改语义，是否补真正的去重（存源地址列或按内容哈希）需另开任务与用户确认。
- **取证过程踩坑（供后来者）**：用 `Copy-Item` 还原被 `git checkout` 覆盖的实现文件会保留**旧 mtime**，Maven 据此判定源码未变、复用上一次（红跑）的 class，导致"改了却仍然红"。还原后必须刷新时间戳或 `mvn clean`。
