## 夹具修正与永久回归

前轮暂停原因是测试夹具错误：使用 C 用户缓存中 Sa-Token 1.43 API，而 backend 实际为 Maven 自定义仓库里的 1.39.0；context.mock 不存在。恢复后核对 1.39.0 jar/sources，使用同一 MockHttpServletRequest 的 SaRequestForServlet / SaResponseForServlet / SaStorageForServlet，并通过 SaTokenContextForThreadLocalStorage.setBox 建立上下文。结束清 ThreadLocal、恢复原全局上下文。生产实现未因夹具故障放宽。

永久测试 UserEmailBindSessionTest 共 6 例：仅旧 Session、已撤销 token、异人 token、只有 token 无 Session 拒绝；有效同人 header / Cookie 两条正向通过。拒绝断言同时要求验证码方法和查询/更新 wrapper 零调用。

既有 UserSessionLifecycleIntegrationTest 扩展：真实登录→重置密码→新请求携旧 Session/token 换绑被拒→查库邮箱不变/Redis 验证码保留；再以新密码登录，构造新请求，经 controller 换绑成功，查库邮箱变化/验证码已消费。新请求只复用凭据，不复制前次请求内部属性。
