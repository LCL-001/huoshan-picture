## 交付

- `AiAssistantOperationManager`（新建）：**prepare**（形状校验 + 归一化 → SHA-1 digest → Redis hash 存规范化计划，TTL 默认 10 分钟，`app.ai.assistant.operation-ttl` 可配）+ **confirm**（Lua 原子"用户/会话/digest/计划一致性全匹配 + 单次删除消费"，消费后按服务端存储计划执行既有 `PictureService#editPictureByBatch` / `#uploadPicture`，loginUser 取自 confirm 请求——确认不绕过 RBAC/额度/URL 安全校验）。
- 端点（AiAssistantController）：`POST /api/ai/assistant/operations/prepare`（引擎带用户凭据调用，T27.6 接线）、`POST /api/ai/assistant/operations/confirm`（前端 T27.7 接线；只收 operationId + chatId + digest，**无业务 payload**）。
- Redis 键 `huoshantuku:ai:assistant:operation:<operationId>`（与 ticket 键隔离，操作 id 为安全随机 32 位 hex）；操作类型仅 `batch_edit` / `url_import`，张数上限 50 / URL 上限 20（与引擎既有工具契约一致）。
- 日志只落元数据（operationId、类型、条数、结果），计划 payload 与用户内容不进日志；URL 入库逐条上报结果，未知失败收敛为"上传失败"，登录态失效提前终止并如实报剩余条数。

## 偏差与执行插曲

- **子代理中断接管**：本任务按项目惯例派发子代理执行，子代理完成了 DTO/VO、controller 接线、三个测试类与 manager 脚手架（常量、两个 Lua 脚本、构造注入）后被运行环境中断（并发超限），`prepare`/`confirm` 方法体未写；主会话审查全部草稿后接手完成并跑绿。
- **审查修正 1（安全）**：草稿的 CONSUME_SCRIPT 只校验"存储 digest 字段 == 调用者回传 digest"，未校验"计划本体与 digest 一致"——存储计划被外部篡改后仍会被消费执行（集成测试 `tamperedStoredPlanFailsClosed` 必红）。已在 Lua 内补 `redis.sha1hex(plan) ~= digest → 拒绝且保留原值`。
- **审查修正 2**：digest 算法定为 **SHA-1**（草稿为 SHA-256）——Lua 侧只有 `redis.sha1hex` 内置可用；该 digest 是服务端存储值的完整性指纹兼确认卡片展示串，非口令哈希，强度足够。VO/DTO 注释与单测断言同步。
- 其余修正：测试类补 `User` import；void 方法桩由 `when(...).thenAnswer` 改 `Mockito.doAnswer().when(...)`。
