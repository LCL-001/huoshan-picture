## 两次 dry-run 救回来的错（都记进脚本注释了）

1. **MySQL 的 `LIKE` 没有 `[...]` 字符类**。我第一版写 `userAccount like 'sec[_]%'`（那是 SQL Server 的语法），dry-run 显示**匹配 0 条**——15 个 `sec_*` 账号会被静默漏删，而脚本会"成功"退出。改用无歧义的 `left(userAccount, 4) = 'sec_'`。
   （顺带记下反向的坑：`'sec_%'` 里的 `_` 是通配符，会连 `secret…` 一起匹配——所以精确前缀别用 LIKE。）
2. **我上一条把 `1234`～`1234567` 与 `admin` 描述成"历史探针账号"是错的**。逐个盘点足迹后：`1234` 有 **2 个空间、144 张图**、是 admin；`admin` 有 2 空间 10 图。这些是你在用的账号，照名字删会造成不可逆的损失。**结论：删之前必须看属主的真实内容足迹，不能照名字猜。**
