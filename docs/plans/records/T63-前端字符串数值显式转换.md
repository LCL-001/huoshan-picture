## 病根（T54 之后的四处隐式强制转换）

T54 把 int64 改成 `string` 后，四处代码靠 JS/echarts **隐式转换**侥幸能跑：

| 位置 | 改前 | 问题 |
|---|---|---|
| `PictureManagePage.vue` 大小单元格 | `(record.picSize / 1024).toFixed(2)}KB` | `/` 隐式转字符串；**缺值 → "NaNKB"**；0 字节显示 "0.00KB"（与统一口径"0 B"相抵）；且这是 `@/utils` `formatSize` 已拥有的那份口径（T58 定的：0 字节是"0 B"、真缺值是"未知"、形参接受 string） |
| `SpaceSizeAnalyze.vue` | `value: item.count` | 图表数据是字符串 |
| `SpaceTagAnalyze.vue` | `value: item.count` | 同上 |
| `SpaceUserAnalyze.vue` | `data: counts`（`item.count` 数组） | 同上 |

`item.count` / `record.picSize` 在 typings 里是 `string`；组件里 `record` 来自表格 slot（`any`），
所以 type-check 一直是 0 错——**类型系统拦不住这类隐式转换**，只能靠显式转换 + 常驻断言守。

## 修复

- **新增 `toNumber`**（`utils/index.ts`）：
  ```ts
  export const toNumber = (value?: number | string | null, fallback = 0): number => {
    const parsed = Number(value)
    return Number.isFinite(parsed) ? parsed : fallback
  }
  ```
  · 真实 `0` 是已知值、不被当缺值（`if (!value) return fallback` 那种写法会把 0 吞掉，与 `formatSize` 修过的坑同源）；
  · 缺值/非数字/NaN → `fallback`（默认 0）；· **id 不走这里**（19 位雪花 id 转 number 丢精度，见下）。
- **大小**改用统一 `formatSize(record.picSize)`：字符串/零/缺值三种形态由既有 `check:format-size` 断言覆盖，
  不新增第二份格式化口径。
- **三处图表**改为 `toNumber(item.count)`：图表输入是 number；缺值画成 0 而不是 NaN 点。
- **id 一律不转**：`Number(...)`/`toNumber(...)` 不得作用于 id 字段（19 位 id 转 double 会静默舍入，
  破坏字符串等值判断——decisions 2026-09-14「id 按字符串透传」与 2026-10-13 T54）。

## 断言怎么写的（两类，都要）

1. **行为断言**（真实 `utils/index.ts` 经 esbuild 转 CJS 后在 node 里断言，同 `check:format-size` 的手法）：
   `'512'→512`、`'0'→0`、`'1.5'→1.5`、`0`（配合自定义 fallback 仍为 0）、`undefined/null/''/NaN/'abc'→0`、
   自定义 fallback 生效、以及 id 往返丢精度的反证。
2. **结构断言**（读四个组件源码）：
   `PictureManagePage` 不得出现对 `picSize` 的裸除法、且大小必须经 `formatSize`；
   三个 analyze 组件的 count 必须经 `toNumber`；
   **四个文件都不得把 id 喂给 `Number`/`toNumber`**（正则 `(?:Number|toNumber)\(\s*[\w.$]*id\b/i` 不得命中）。

## 已知限制 / 未覆盖

1. **结构断言是源码级正则**，钉的是"转换发生在哪、id 没被转"，不是那几行的运行时行为。
   行为侧只对两个助手（`toNumber` 行为断言、`formatSize` 由 `check:format-size`）成立。
2. **同一个转换现在有两种写法**：`SpaceCategoryAnalyze` / `SpaceRankAnalyze` 在 T54 时代已是内联
   `Number(item.count ?? 0)` / `Number(item.totalSize ?? 0)`（比例/大小各一处），**本轮未改**（T63 范围外、不顺手重构）。
   要不要收敛到 `toNumber` 另开任务。
3. **只扫了 analyze 三件套 + 管理页大小单元格**：这是本轮 review 认定的隐式转换点；
   其他页面若还有对字符串数值做算术的地方，本轮没有系统性排查（没有 lint 规则能拦这一类）。
4. **未做浏览器人工验收**：大小单元格文案从 `(x/1024).toFixed(2)KB` 变成 `formatSize` 口径
   （`512 B` / `1.00 KB` / `1.00 MB` / 缺值`未知`），图表 data 变成 number——**都没有真机看过**，
   证据 = type-check / eslint / 六个检查脚本。
