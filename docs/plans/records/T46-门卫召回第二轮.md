## 问题

范围门卫对**每条**请求做一次无工具模型分类，输入只含"最近放行轮的 **AssistantMessage 文本**"——
USER 行仅作轮边界、文本从不进输入。后果：

- **F1（P1）**：T44 的「操作结果」事实行（USER 角色）与用户原始请求（空间名、目标图片、操作类型）都进不了门卫；
  真机上**已完成**写操作的追问「刚才那个批量编辑完成了吗？结果怎么样」被误拒——与 T44 的初衷（让下一轮能读到"已执行"）直接矛盾。
- **F2**：门卫读回放视图，而回放经 `MessageConverter` 剥掉了 `toolCalls`，`composeRoundContext` 的"（上一轮工具：…）"**生产恒空**（单测用裸 memory，假绿）。
- **F3**：首个 `IN_SCOPE|OUT_OF_SCOPE` 子串定生死（否定式前言被首个 OUT_OF_SCOPE 否决）；能力枚举未写"批量编辑图片"。
- **F4**：与 F1 同源——1 轮窗口丢锚点，召回实质是词法级。

  丢弃等于拒绝话术的行，USER 至多 2 行、ASSISTANT 至多 1 行，各截断 500 字，按原序拼在 System 之后。
  **修订 T43 A1 的"USER 行不进输入"**（拒绝话术仍排除）。
- **A2'**：删除从 `AssistantMessage.getToolCalls()` 收集工具名与 `composeRoundContext` 的工具名后缀（生产恒空的死路径）；
  测试改用回放代表性 memory。
- **A3'**：`SCOPE_CAPABILITIES_EN` 补写/编辑操作；`SCOPE_PROMPT` v2→v3（写明写/编辑操作在范围内、"追问已准备/已确认的变更是否完成"也算范围内）；
