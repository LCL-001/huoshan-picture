# T44 记录 — 确认执行结果回灌引擎

> 2026-10-12 完成。字据见 `docs/decisions.md` 2026-10-12 行与 `docs/designs/2026-10-12-确认门收尾与结果回灌设计.md`。
> 来源：2026-10-12 只读审查 P1-2。

## 问题

写操作确认执行成功后，链路只发生在 backend（`POST /ai/assistant/operations/confirm`），**不碰引擎**；
而引擎回放（`MessageConverter.toReplayMessages`）又丢掉 TOOL 行与空文本 assistant 决策行。
于是下一轮模型只看到用户的原始请求与它自己那句"请确认"，**读不到"已执行成功"这一事实**，
可能再生成 prepare、再要确认，或答"尚未完成"——前端卡片状态、backend Redis 状态、引擎模型上下文三者分叉。

## 改动

引擎：
- `HuoshanAssistantSession` 增常量 `OPERATION_RESULT_PREFIX`（`【系统记录】`）。
- `HuoshanAssistantController` 增 `POST /ai/huoshan/conversations/{chatId}/operation-results?userId=`（body `{"content":"..."}`），
  经 `HuoshanAssistantSession.owner` 校验 + 确定性 conversationId 派生，以 **USER 角色 + 前缀**写入该会话记忆；
  鉴权沿用既有 `HeadlessApiKeyInterceptor`。
- `ChatHistoryAssembler.isInternalPrompt` 增该前缀 → 前端历史不出现该行（维持"回放无卡片"现状），模型回放仍保留。

backend：
- `AiAssistantOperationManager.operationResultNote`（public static）：生成模型面中文说明。
- `AiAssistantProxyManager.recordOperationResult`：POST 到引擎内部端点，带内部密钥，**best-effort**（IO 失败只 warn）。
- `AiAssistantController.confirmOperation`：confirm 成功后回灌；再兜一层 RuntimeException，回灌失败绝不改变 confirm 的返回。

## 边界与未做

- 仅覆盖"已执行（成功 / 部分失败）"；confirm **硬失败**（抛异常）不记录（卡面已就地报错，且无结果可报）。
- 结果事实对前端历史隐藏（前缀过滤）；`MessageConverterReplayTest` 保证它仍在模型可见序列里。
- 不改确认门安全设计（Lua 原子消费、凭据一致性、URL SSRF 防护）。
