#### 负向控制（规则 12）：摘掉守卫 → 红，且**留下了真实后果**

把 `resolveInsideDir` 的 `return target.startsWith(base) ? target : null;` 改成 `return target;` 后：

- `FileOperationToolPathGuardTest` **4/6 红**（`rejectsParentTraversal` / `rejectsDeeperTraversal` / `rejectsAbsolutePaths` / `traversalWriteLeavesNoFileOutside`）；未红的 2 例是空名与放行侧——我的补丁只摘了前缀比较，没摘空名判断，符合预期。
- 失败信息直接给出漏洞的形态：`readFile("/etc/passwd")` 返回 `Error reading file: File not ...`——**它真的去打开了那个路径**，只是因为 Windows 上没有该文件才失败。
- **并且真的写成功了外部的文件**：`writeFile("../../Windows/win.ini", ...)` 在仓库根下创建了 `Windows/win.ini`，内容正是用例里的字面量 `should never be written`。两处残留（`ai/agent/guard-test-should-not-exist.txt` 与 `Windows/`）已删除，工作区已核实干净。

**这次负向控制暴露了我测试设计的两处问题，已修正**（比对"看起来通过了"更重要）：

1. `traversalWriteLeavesNoFileOutside` 原来断言"外部文件不存在"，会被上一次跑坏的运行留下的残骸污染（恢复守卫后它仍然红）。现改为：断言前先 `deleteQuietly` 清痕、断言后在 `finally` 里再清一次，使判定只反映当前代码。
2. 原来对**绝对路径也执行写**——负向控制下会真的去写 `C:\Windows\win.ini` 这类系统路径。现改为：绝对路径只验**读**；要验"绝对路径的写也被拒"时，改用系统临时目录下的路径，万一守卫被摘掉，副作用只是临时目录里一个文件。相对穿越的写则改用落点在 `tmp/`（已 gitignore）的名字。

#### 真机验证：回环绑定确实生效（两侧都验）
