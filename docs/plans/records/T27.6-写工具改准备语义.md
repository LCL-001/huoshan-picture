> 2026-09-29 完成。协议权威口径见 `docs/plans/2026-09-16-T27-AI助手后端安全加固实施计划.md` T27.6 节；确认门协议生效口径见 `docs/decisions.md` 2026-09-29 行。commit `086822c`。

## 交付

- **两个 prepare 工具**（`tools/huoshan/`，prototype、携带调用者凭据组与 chatId）：
  `prepareBatchEditPictures` / `prepareUrlImportPictures` —— 调 backend `POST /api/ai/assistant/operations/prepare`（T27.5 端点）提交规范化操作计划（**零写库**），成功后返回 `status=pending_confirmation` + operationId/digest + 卡片摘要行；本地先做与后端一致的形状校验与归一化（trim / 去重 / 丢空项 / 上限 50 张 / 20 条 / 仅 http(https) 直链），保证卡片摘要与后端存储的计划同源。
- **SSE 协议新增 Confirmation 事件**（`AgentEvent.Confirmation` → 帧 `event=confirmation_required`，字段 operationType/operationId/digest/summary）；`SseAgentEventListener` 增帧映射。协议"三处同步"完成两处：引擎监听器 + 代理侧测试（透传断言）；前端 `assistantSse.ts` 分流在 T27.7。
- **循环产出确认卡片**（`ToolCallAgent.act`）：按**载荷形状**识别待确认操作（`status=pending_confirmation` 且带 operationId/digest，经 `normalizeToolResponseData` 还原引号包裹形态后解析），在工具步之前发 Confirmation 帧；识别不依赖工具名，循环保持与图库工具解耦。
- **直接写工具删除**：`BatchEditPicturesTool` / `BatchUploadByUrlTool` 两类、`BatchEditResult` / `BatchUploadResult` / `UploadResultItem` 三个 DTO、`HuoshanApiClient.batchEditPictures` / `uploadByUrl` 两个方法、`HuoshanWriteToolsTest` 全部移除——引擎从此没有"模型触发即写库"的路径。
- **装配与提示词**：工厂恒挂两个 prepare 工具（`assistantTools` 签名加 chatId，控制器透传）；系统提示词与 visionTagger 文案从"只读边界"改为"准备→确认→执行"口径（模型不得声称已写入、不重复提交、目标不清先问）。

## 负向控制（plan T27.6 要求）

- 装配层：`HuoshanToolFactoryTest.directWriteToolsAreGoneAfterConfirmationGate` 断言 `batchEditPictures` / `batchUploadByUrl` 不在工具清单（模型即使构造旧工具名也无处执行——Spring AI 只按注册回调解析）。
- 请求层：`HuoshanPrepareToolsTest.prepareFlowNeverTouchesDirectWriteEndpoints` 断言 prepare 全流程对桩图库只发 `/ai/assistant/operations/prepare`，`/picture/edit/batch`、`/picture/upload/url` 请求数为 0（直接写方法已在客户端删除，属结构性保证）。
