# T27.2 记录 — 助手代理取消竞态与错误体有界读取

> 2026-09-29 完成（T27 收口的最后一项）。协议口径见 `docs/plans/2026-09-16-T27-AI助手后端安全加固实施计划.md` T27.2 节；R4/R7 的原始判定见 `docs/plans/records/T27-first-release.md`（当时列为"尚未修"）。commit `cb3ac2c`。

## 交付

- **R4 取消竞态**（`AiAssistantProxyManager` 新增包内静态类 `Upstream`，替代裸 `AtomicReference`）：取消状态与上游连接登记原子配合——`cancel()` 先置位再断开已登记连接；`forward()` 在 `open()` 前先看取消位（客户端早断即不建连）；`register()` 登记后**复查**取消位，命中则立即 `disconnect()` 并返回 false，worker 不再进入 `getResponseCode()` / `relay()`。旧实现在"取消早于建连"和"取消落在建连与登记之间"两个时序下都会漏：取消侧看到的登记是 null，worker 随后照常跑完一整轮（白烧一次完整 LLM 调用链 + 上游负载）。
- **R7 错误体有界读取**：`readErrorBody` 从 `readLine()` 改为**按字符块读**、总长硬上限 `ERROR_BODY_MAX_CHARS`(2048)——旧写法用 `readLine()` 整行读进内存，"下一行才查长度"的上限被一条没有换行的超长体直接绕过，且读到多长就返回多长。新增 `withoutControlChars`：进解析/日志前去掉 ISO 控制字符（含 `\u000B` 这类会被日志查看器当换行渲染的字符、ANSI 转义）与 U+2028/U+2029；JSON 的空白只允许出现在 token 之间，清洗放在解析之前无副作用。

## 红绿与门禁

- **行为级先红（3 条，修复前可编译、真实失败）**：`cancelBeforeWorkerStartsSkipsUpstreamEntirely`（门控执行器扣住 worker → 触发 emitter 超时回调 → 放行：上游请求数 **1≠0**）；`overlongSingleLineErrorBodyIsBoundedAndTailNeverReachesTheUser`（8000 字符单行体：**TAIL-MARKER 出现在用户可见的 error 帧里**）；`errorBodyControlCharactersNeverReachTheLog`（Logback `ListAppender` 抓日志：**`\u000B` 与 `\u001b` 原样进日志**）。红跑 `AiAssistantProxyManagerTest` = 23 例 3 失败，其余 20 例全绿。
- **结构性红（2 条，无法在修复前编译，同 T27.5 先例）**：`registerAfterCancelDisconnectsImmediatelyAndRefusesToProceed`（取消落在建连与登记之间 ⇒ register 回 false 且断开一次）与 `cancelAfterRegisterDisconnectsTheRegisteredConnection`（取消晚于登记 ⇒ 断开已登记连接，重复断开只生效一次）。二者依赖新类 `Upstream`，与实现同批落地。
- **后绿**：`AiAssistantProxyManagerTest` **25/25**；提交门禁 backend **139** / 引擎 **199** 全绿。

## 已知边界

- **取消与"建连"之间仍有一个纳秒级窗口**：cancel 恰落在 `register` 的复查之后、`getResponseCode()` 之前时，会多打一次上游请求——随后首帧 `emitter.send` 失败即收尾，代价是一次连接而非一整轮。要用额外同步彻底消除得不偿失，本轮接受。
- **2048 字符处截断后多半不再是合法 JSON** ⇒ 用户收到通用文案"引擎响应异常（HTTP xxx）"（原来会拿到超长原文）。这是有意的方向：超长错误体不是给用户读的，原文仍进（已清洗、已截断的）服务端日志。
- 读错误体仍受 `readTimeout` 约束（未改）；`relay()` 的多行 data 拼接与 `[DONE]` 语义未动。
- 阶段遗留的口径不变：R6（引擎 JSON message 白名单）在第一阶段已按"非 JSON 一律通用文案"收口，本轮未扩大用户可见的错误文案面。
