## 根因（最值钱的一条）

**生成 api 的 `requestType: 'form'` 是最大单点**：它不在 `AxiosRequestConfig` 里，导致 axios 重载匹配失败，`request<T>` 的 `T` 悬空，`res.data.code/.data/.message` 全部报"Property 'code' does not exist on type `T`"。3 行这类代码连带制造 **15 个错误**（3 个 `TS2353` + `GlobalHeader`/`ImageCropper`/`PictureUpload` 各 4 个级联）。已用临时探针复核：去掉该属性后类型立刻恢复为 `AxiosResponse<BaseResponseString_>`。axios 运行时忽略该属性、`FormData` 自动设 multipart，故**行为等价**。同类根因还有：analyze 组件把数组类型写成单对象（25 个错误）、antd 回调参数未标注、`route.query` 是 `string` 而目标字段是 `number`、`res.data.data` 可选性未处理。

## 行为边（非纯类型、已逐条确认等价或有据）

- 删 `requestType`（axios 忽略）；删 `AddPicturePage` 传给编辑接口的 `spaceId`（后端 `PictureEditRequest` 无此字段）；删 `UserRegisterPage` 传给注册接口的 `captchaUuid`（后端 `UserRegisterRequest` 无此字段，图形验证码在"发邮件码"端点校验）——三处都是**已在发送但后端不读**的死字段。
- `AddSpacePage` 的 `:key="spaceLevel.level"` → `spaceLevel.value`：后端 `SpaceLevel` 只有 `value`，原 key 恒为 `undefined`（潜在小 bug，已修正）。
- `SpaceDetailPage`/`AddSpacePage`/`SearchPicturePage`/`SpaceAnalyzePage`/`SpaceUserManagePage`：路由/属性里的字符串 id 统一 `Number(...)`（后端以 number 收）。
- admin 三页 `doDelete(id: string)` → `number`；`doTableChange(page: any)` → 结构类型；`showTotal(total: number)`。
- `PictureSearchForm` 日期入参 `.toDate()` → `.toISOString()`：`JSON.stringify(Date)` 本就产出 ISO 串，**序列化结果不变**。
- `PictureDetailPage` 删掉 `<Transition name="detail-fade">`：无 `appear`、单子节点、`mode="out-in"` → 从不触发动画，属惰性结构。
- `ShareModal`：`props` 改为可选字段 + 模板用 `props.title`/`props.link`。**踩到的坑**：`withDefaults(defineProps<Props>(), ...)` **不赋给变量时被 vue-tsc 忽略**（props 变必填，两个调用点立刻红）——赋值后恢复；同批把 `any[]` 的 `notifications` 换成 `API.UserNotification[]`，牵出 `doDeleteNotification(id?: number)` 的守卫。
- `constants/picture.ts`：审核状态表加 `Record<number, string>` 注解、索引用 `Number(key)`；下拉选项的 `value` **仍是 string**（未改后端 `reviewStatus` 口径）。
- `catch (e: any)` 一律收敛为 `catch (e)` + `e instanceof Error ? e.message : String(e)`（与仓内 `AiTagPictureModal` 既有写法一致）；空用的 catch 变量直接去掉绑定。
- `utils/pictureEditWebSocket.ts`：新增 `PictureEditMessage` 接口（字段对齐后端 `PictureEditResponseMessage`：`type/message/editAction/user`），`eventHandlers` 改 `Record<string, PictureEditHandler[]>`，`triggerEvent` 入参 `unknown` + 一处 `as PictureEditMessage`；调用点（`ImageCropper`）零改动。
