# T35 附：mimo-v2.5 与 mimo-v2.6-flash 的速度实测（2026-09-28）

> 这是 T35 的**补充证据**（单独一份记录，写一次不再编辑）：`docs/plans/records/T35-模型升级.md` 的「没验证什么」里写着"速度对比未知"，本文件把它补上。
> 口径与范围见 `docs/decisions/2026-09-28-model-upgrade.md`。本测量是**用户提问触发的一次性探针**，不是任务验收项。

## 结论

同一个提示词、同样的配置（关思考模式、temperature 0.4，与引擎一致）、同一次会话内交替测量：

| 指标（4 次取中位） | `mimo-v2.5` | `mimo-v2.6-flash` | 倍率 |
|---|---|---|---|
| **解码速度** | 59.1 tok/s | **110.3 tok/s** | **1.9×** |
| 端到端总耗时（1092 token） | 23700 ms | **13792 ms** | 1.7× |
| 首字延迟 TTFT | 5722 ms | **1407 ms** | 4.1× |

**解码速度的 8 次测量无重叠**——v2.6-flash 的 4 次（84.1 / 87.2 / 133.4 / 141.1）全部高于 v2.5 的 4 次（53.9 / 54.1 / 64.1 / 64.5）。这一条比中位数的倍率更可信。

## 为什么前两轮测量不可用（记下来避免下次重踩）

1. 第一轮用"用三句话说明…"，输出只有 19~65 token：墙钟时间被固定开销（排队 + 预填充 + 首字）主导，算出的 tok/s 在 10.9~34.4 之间乱跳，两个型号无法区分。
2. 第二轮改成"写 500 字左右"，**输出长度失控**：`mimo-v2.5` 三次都只吐 62~67 token 就 `finish=stop`（没按提示词写长文），`mimo-v2.6-flash` 则给出 114 / 900 / 631。长度不一致时比 tok/s 是假的。
3. 第三轮换成"从 1 数到 300"（**输出长度由提示词钉死**）+ **流式**：两个型号每次都恰好 1092 token，且流式能把预填充/排队从解码速度里剥出去（用"首字到最后字"的时间算），这才得到可用数据。

**方法论沉淀**：比模型解码速度要 ① 提示词钉死输出长度、② 用流式算 TTFT 与解码段、③ 至少 4 次取中位。非流式 + 自由长度的对比不要信。

## 复现方式（可复跑）

需要本机那份**不入库**的 `ai/agent/src/main/resources/application-local.yaml`（脚本从里面读 `MIMO_API_KEY`，密钥不经过命令行与输出）。脚本内容：

```js
const fs = require('fs');
const YAML = 'ai/agent/src/main/resources/application-local.yaml';   // 相对仓库根
const URL = 'https://api.xiaomimimo.com/v1/chat/completions';
const PROMPT = '请从 1 数到 300，数字之间用英文逗号分隔，不要换行，不要任何其它文字。';
const MODELS = ['mimo-v2.5', 'mimo-v2.6-flash'];
const RUNS = 4;

const key = fs.readFileSync(YAML, 'utf8').match(/MIMO_API_KEY:([^}]+)/)[1].trim();

async function once(model) {
  const t0 = Date.now();
  const res = await fetch(URL, {
    method: 'POST',
    headers: { Authorization: `Bearer ${key}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({
      model,
      messages: [{ role: 'user', content: PROMPT }],
      max_completion_tokens: 1500,
      temperature: 0.4,
      thinking: { type: 'disabled' },
      stream: true,
      stream_options: { include_usage: true },
    }),
  });
  if (!res.ok) throw new Error(`HTTP ${res.status} ${(await res.text()).slice(0, 200)}`);
  const reader = res.body.getReader();
  const dec = new TextDecoder();
  let buf = '', ttft = null, tokens = 0, usage = null;
  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    buf += dec.decode(value, { stream: true });
    const lines = buf.split('\n');
    buf = lines.pop();
    for (const line of lines) {
      const s = line.trim();
      if (!s.startsWith('data:')) continue;
      const p = s.slice(5).trim();
      if (!p || p === '[DONE]') continue;
      let j; try { j = JSON.parse(p); } catch { continue; }
      if (j.usage) usage = j.usage;
      const d = j.choices && j.choices[0] && j.choices[0].delta;
      if (d && (d.content || d.reasoning_content)) { if (ttft === null) ttft = Date.now() - t0; tokens += 1; }
    }
  }
  const total = Date.now() - t0;
  const out = usage ? usage.completion_tokens : tokens;
  return { ttft, total, out, decode: ttft !== null && out > 1 ? (out - 1) / ((total - ttft) / 1000) : NaN };
}

(async () => {
  for (const model of MODELS) {
    const rows = [];
    for (let i = 1; i <= RUNS; i++) {
      try { rows.push(await once(model)); }
      catch (e) { console.log(`${model} run${i} ERROR: ${e.message}`); }
    }
    rows.forEach((r, i) => console.log(
      `${model.padEnd(16)} run${i + 1}  ttft=${String(r.ttft).padStart(5)}ms  total=${String(r.total).padStart(6)}ms  out=${String(r.out).padStart(4)}  decode=${r.decode.toFixed(1)} tok/s`));
  }
})();
```

运行：`node mimo-speed-probe.js`（Node 24 实测可用；HTTP 200 即说明账号有该型号权限）。

## 本测量**没有**覆盖（别当成结论）

- **不是端到端智能体延迟**。图库助手的实际耗时 = 每次模型调用 × 步数（上限 20）+ 工具网络时间（Pexels、图片下载）。本测量只估了"每次模型调用"里占主导的解码段，外推时别直接拿 1.9× 套到场景耗时上。
- **不是质量对比**。提示词是"数到 300"，只测吐字速度，不测推理/工具调用/多模态的正确性。
- **没开思考模式**。与引擎配置一致（`thinking.type=disabled`）；若某天打开思考模式，两者的差距可能完全不同。
- **绝对值含网络与服务端排队噪声**：TTFT 在 v2.5 上跨了 415ms~23645ms（有 23.6s 的长队异常），因此中位数只作指示；**可依赖的是"8 次解码速度无重叠"这一相对结论**。
- **单机单次会话**，未做跨时段/跨地域重复。
