## 风险与对策

1. **`List<String>` 工具参数能否被 Spring AI 生成数组 schema**：模型靠 schema 才能正确传 id 列表。对策：本计划第一个任务就写**schema 契约测试**（`ToolCallback.getToolDefinition().inputSchema()` 里 `pictureIdList`/`fileUrls` 必须是 `array`），不通就退化成"逗号/换行分隔字符串 + 工具内解析"（并在 docs 记口径）。
2. **写类工具让模型改真实数据**：提示词必须写清"只在用户明确要求时改、改前说清改哪几张、不得编造 id"，且工具返回如实反映"图库可能静默跳过"。这是档 3 与档 2 最大的行为差异，要在 T12 场景里专门验。
3. **visionTagger 的图片可见性**：模型要能直接取 `picture.url`（COS 地址）。若线上 COS 非公读，多模态输入需改用签名 URL——T12 真机联调时确认，必要时由图库侧出临时签名（属 backend 改动，需单独立项）。
4. **`batchUploadByUrl` 的时间预算**：每条上传含"图库下载 + COS 上传"，代理 read-timeout 6 分钟、单批上限要有界（倾向 20 条/次），否则一步卡死对话。
