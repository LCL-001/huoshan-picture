# F20：页面身份与上传生命周期

## 一句话
页面缓存只能属于当前登录身份，上传/编辑状态只能属于当前路由上下文。

## 怎么用
同账号从图片详情返回列表可继续浏览；退出或换账号后不复用前账号页面。编辑图片后点击“上传图片”应得到空白新增上下文，而不是继续修改旧图。

## 怎么实现
现有 PageTransition 为 HomePage、SpaceDetailPage 启用 KeepAlive。T70 让缓存容器跟随登录身份销毁重建；身份变化或空间访问失败时清除旧内容与权限，重建图片列表/批量编辑子树以销毁分享链接和表单，并拒绝迟到请求回填；T69 计划让 AddPicturePage 随编辑对象/空间变化重新初始化，并拒绝旧请求回包。保留服务端上传接口 id=替换、无 id=新增的契约，不以按钮文案代替请求身份。

## 怎么验证
T70 执行 `npm run check:private-page-cache`；21 组永久组件断言、负向控制与安全构建命令见 `docs/plans/records/T70-私有页面缓存身份隔离.md`。T69 验收要求见原设计，状态以 plan 为准。真实浏览器复跑入口、覆盖范围与断言边界见 `docs/evidence/2026-10-17-t68-t70-final-acceptance.md`；同上下文详情／上传回包优先级亦需单独验证，不能只测路由切换。

## 已知限制
不改变 COS 图片地址本身的访问策略；缓存隔离不是服务端授权。内存组件测试不替代真实浏览器；本地浏览器覆盖与剩余边界见最终验收报告，二维码图案检查不等于扫码识别，也不代表生产 nginx／TLS 或完整动画验证。首页分页游标及其它 P2 不在本批。
