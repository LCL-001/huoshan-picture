# F19：邮箱绑定安全

## 一句话
邮箱决定账号找回渠道，绑定/换绑须验证当前有效登录身份与新邮箱所有权。

## 怎么用
正常登录后在个人信息面板填写新邮箱并完成验证码；登录态过期或改密后先重新登录。

## 怎么实现
入口为 UserController 的 `/user/email/bind`，实现为 UserServiceImpl.bindEmail。图库同时使用 Spring Session 与 Sa-Token；T68 复用 LoginSessionValidator，要求两套身份有效且一致，再验证新邮箱验证码及唯一性，最后更新邮箱。改密仍沿用现有 Sa-Token 全部撤销机制，不扩大成全站会话迁移。

## 怎么验证
永久回归为 UserEmailBindSessionTest 和 UserSessionLifecycleIntegrationTest；负向控制、真实 MySQL/Redis 验证与复跑命令见 `docs/plans/records/T68-邮箱绑定双登录态校验.md`。

追加真实 HTTP 脚本、原始输出与验收边界见 `docs/evidence/2026-10-17-t68-t70-local-e2e.md`；不能以该证据替代真实邮件投递或浏览器验收。

## 已知限制
不宣称所有 Spring Session 在改密后立即失效；其它已接受残余见 decisions 会话生命周期口径。本说明不能替代服务端逐资源 RBAC。
