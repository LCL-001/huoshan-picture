# F19：邮箱绑定安全

## 一句话
邮箱决定账号找回渠道，绑定/换绑须验证当前有效登录身份与新邮箱所有权。

## 怎么用
正常登录后在个人信息面板填写新邮箱并完成验证码；登录态过期或改密后先重新登录。

## 怎么实现
入口为 UserController 的 `/user/email/bind`，实现为 UserServiceImpl.bindEmail。图库同时使用 Spring Session 与 Sa-Token；T68 计划复用 LoginSessionValidator，要求两套身份有效且一致，再验证新邮箱验证码及唯一性，最后更新邮箱。改密仍沿用现有 Sa-Token 全部撤销机制，不扩大成全站会话迁移。

## 怎么验证
按 `docs/designs/2026-10-17-P1账户与页面状态修复计划.md` 的 T68 红绿验收；最终永久测试与执行结果由 plan 对应条目指向。

## 已知限制
不宣称所有 Spring Session 在改密后立即失效；其它已接受残余见 decisions 会话生命周期口径。本说明不能替代服务端逐资源 RBAC。
